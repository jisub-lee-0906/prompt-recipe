# 카드 레이아웃

> 한 줄 정의: 카드 레이아웃은 여러 개의 객체를 독립적인 카드 단위로 묶어 반복 배치하는 화면 구성 방식입니다.

## 왜 중요한가

카드 레이아웃은 보기 좋은 박스를 나열하는 문제가 아니라, 정보의 우선순위와 클릭 구조를 설계하는 문제입니다. AI IDE에게 "카드처럼 보여줘"라고만 하면 표면적인 박스 UI가 나오기 쉽고, 무엇이 카드의 핵심 정보인지 빠지기 쉽습니다.

## 언제 쓰는가

- 문서, 상품, 템플릿, 프로젝트처럼 독립 객체를 반복해서 보여줄 때
- 제목, 설명, 태그, 액션 버튼처럼 여러 정보 조각을 묶어 보여줄 때
- 리스트와 그리드 전환이 가능한 화면을 설계할 때

## 언제 쓰지 말아야 하는가

- 행 단위 비교가 중요한 데이터 테이블일 때
- 텍스트 밀도가 높고 카드로 나누면 오히려 시야가 분산될 때
- 한 화면에 너무 많은 카드가 들어가 카드 간 구분이 흐려질 때

<Callout type="info" title="카드는 하나의 객체를 대표해야 합니다">
카드 하나를 봤을 때 그 카드가 무엇을 의미하는지 바로 이해되어야 합니다. 정보 우선순위가 흐리면 카드 수가 많아질수록 훑어보기 경험이 급격히 나빠집니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

카드 레이아웃을 요청할 때는 아래를 같이 말해야 합니다.

- 카드 안에 들어갈 핵심 정보가 무엇인지
- 카드 전체 클릭인지, 내부 버튼 클릭인지
- 반응형 열 수가 어떻게 바뀌는지
- 빈 상태와 로딩 상태도 같이 필요한지

<PromptCodeBlock>
문서 목록을 카드 레이아웃으로 바꿔주세요.
각 카드에는 제목, 짧은 설명, 태그, 예상 읽기 포인트를 보여주고 카드 전체를 클릭하면 상세 문서로 이동하게 해주세요.
데스크톱은 3열, 태블릿은 2열, 모바일은 1열로 배치해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
템플릿 갤러리를 카드 레이아웃으로 만들어주세요.
각 카드에는 썸네일, 제목, 한 줄 설명, `미리보기` 버튼과 `사용하기` 버튼을 넣어주세요.
hover 상태에서는 카드가 살짝 떠오르는 느낌만 주고, 지나친 그림자나 과한 애니메이션은 피해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
프로젝트 대시보드의 최근 프로젝트 영역을 카드 레이아웃으로 구성해주세요.
카드 안에는 프로젝트명, 마지막 수정일, 상태 배지, 참여자 수를 보여주고, 카드 오른쪽 위에는 더보기 메뉴를 배치해주세요.
프로젝트가 없을 때는 카드 그리드 대신 빈 상태를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="카드 안에 너무 많은 정보를 넣으면 훑어보기 성능이 떨어집니다">
카드는 빠르게 비교하고 고르는 데 강하지만, 한 카드 안에 정보가 지나치게 많으면 오히려 테이블보다 읽기 어려워집니다. 핵심 정보만 두고 세부 정보는 상세 화면으로 보내는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 카드 하나가 하나의 객체를 명확하게 대표하는가
- 제목, 설명, 태그 같은 정보 우선순위가 안정적인가
- 클릭 가능한 영역이 일관적인가
- 반응형 열 수와 간격이 자연스러운가
- 빈 상태와 스켈레톤도 함께 설계되었는가

## 자주 헷갈리는 개념 비교

### 카드 레이아웃 vs 리스트 렌더링

- 카드 레이아웃은 화면 배치 패턴입니다.
- 리스트 렌더링은 데이터를 반복 출력하는 구현 개념입니다.

### 카드 레이아웃 vs 데이터 테이블

- 카드 레이아웃은 객체 단위 훑어보기에 강합니다.
- 데이터 테이블은 열 단위 비교에 강합니다.

### 카드 레이아웃 vs 히어로 섹션

- 카드 레이아웃은 반복 항목을 다룹니다.
- 히어로 섹션은 페이지의 핵심 메시지 하나를 강조합니다.
