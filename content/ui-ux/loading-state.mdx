# 로딩 상태

> 한 줄 정의: 로딩 상태는 화면이 아직 준비되지 않았다는 사실과 곧 어떤 내용이 나타날지를 예측 가능하게 보여주는 UI입니다.

## 왜 중요한가

사용자는 기다리는 것 자체보다 "지금 뭔가 되고 있는지 알 수 없는 상태"를 더 답답해합니다. AI IDE에게 로딩 상태를 구체적으로 요청하면 단순 스피너 하나가 아니라, 실제 레이아웃을 닮은 스켈레톤, 버튼 비활성화, 중복 요청 방지까지 같이 설계할 수 있습니다.

## 언제 쓰는가

- 페이지 진입 직후 데이터를 불러오는 동안
- 검색 조건이 바뀌어 목록을 다시 불러오는 동안
- 저장, 삭제, 업로드처럼 완료까지 잠시 기다려야 하는 동안

## 언제 쓰지 말아야 하는가

- 응답이 거의 즉시 끝나는 작업에 과한 로딩 애니메이션을 넣을 때
- 실패 상태인데 계속 로딩처럼 보이게 만들 때
- 이미 일부 콘텐츠는 보여줄 수 있는데 화면 전체를 불필요하게 막을 때

<Callout type="info" title="좋은 로딩 상태는 기다림을 설명합니다">
사용자가 무엇을 기다리고 있는지 짐작할 수 있어야 합니다. 문서 본문을 기다리는지, 버튼 제출을 기다리는지, 목록 갱신을 기다리는지에 따라 로딩 표현도 달라져야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="로딩 중이면 스피너 넣어주세요."
  goodPrompt="문서 상세 페이지 로딩 중에는 제목, 본문, 우측 TOC 자리까지 실제 구조를 닮은 스켈레톤 UI를 보여주세요. 버튼 클릭 후 저장 중일 때는 해당 버튼 안에서만 로딩 상태를 보여주고 중복 클릭은 막아주세요."
/>

## 더 좋은 요청으로 바꾸는 방법

로딩 상태를 요청할 때는 아래를 같이 말해야 합니다.

- 어느 영역이 로딩 중인지
- 전체 화면 로딩인지, 일부 영역 로딩인지
- 사용자가 기다리는 동안 무엇을 할 수 있는지
- 버튼 중복 클릭을 막을지

<PromptCodeBlock>
문서 상세 페이지 로딩 중에는 제목, 본문, 우측 TOC 자리까지 실제 구조를 닮은 스켈레톤 UI를 보여주세요.
로딩이 끝나면 레이아웃이 크게 흔들리지 않도록 최종 콘텐츠와 비슷한 높이와 폭을 유지해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 필터를 바꿨을 때 목록 영역만 부분 로딩되게 해주세요.
페이지 전체를 막지 말고, 기존 헤더와 필터 바는 유지한 채 결과 목록 자리에서만 스켈레톤이나 로딩 메시지를 보여주세요.
로딩 중에는 중복 요청이 과하게 쌓이지 않도록 조심해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
저장 버튼을 누르면 버튼 안에서만 로딩 상태를 보여주세요.
버튼 텍스트는 `저장 중...`으로 바꾸고, 완료되면 성공 토스트를 보여주세요.
저장 중에는 같은 버튼을 다시 누를 수 없게 비활성화해주세요.
</PromptCodeBlock>

<Callout type="warning" title="긴 로딩에는 상태 설명이 더 필요합니다">
몇 초 이상 기다려야 하는 작업이라면 단순 스피너보다 `업로드 중`, `문서 분석 중`처럼 맥락을 알려주는 문구가 필요합니다. 사용자가 기다릴 이유를 이해해야 이탈이 줄어듭니다.
</Callout>

## 구현 체크리스트

- 사용자가 무엇을 기다리는지 알 수 있는가
- 전체 로딩과 부분 로딩을 구분하는가
- 완료 후 레이아웃 점프가 과하지 않은가
- 로딩 중 중복 클릭이나 중복 요청을 막는가
- 실패 시 에러 상태로 자연스럽게 넘어가는가

## 자주 헷갈리는 개념 비교

### 로딩 상태 vs 스켈레톤

- 로딩 상태는 준비 중임을 알려주는 전체 개념입니다.
- 스켈레톤은 그 로딩 상태를 표현하는 한 가지 시각적 방식입니다.

### 로딩 상태 vs 빈 상태

- 로딩 상태는 아직 결과를 가져오는 중입니다.
- 빈 상태는 결과가 0개로 확정된 상태입니다.

### 로딩 상태 vs 비활성 버튼

- 로딩 상태는 진행 중임을 보여줍니다.
- 비활성 버튼은 현재 행동할 수 없음을 보여줍니다.
