# 이벤트 트래킹

> 한 줄 정의: 이벤트 트래킹은 사용자의 행동을 이름과 속성을 가진 이벤트로 기록해 제품 분석과 의사결정에 활용하는 방식입니다.

## 왜 중요한가

기능을 출시해도 실제로 사용자가 어디에서 이탈하는지, 어떤 버튼을 누르는지, 무엇이 잘 안 되는지 모르면 개선이 감에 의존하게 됩니다. AI IDE에게 "분석 붙여줘"라고만 말하면 이벤트 이름이 제각각이거나 중요한 속성이 빠지기 쉬워서 이벤트 설계 자체를 먼저 지시해야 합니다.

## 언제 쓰는가

- 가입, 결제, 검색, 공유처럼 핵심 행동을 측정할 때
- 퍼널 이탈 지점을 확인하고 싶을 때
- 기능 사용률과 성공 여부를 정량적으로 보고 싶을 때

## 언제 쓰지 말아야 하는가

- 제품 질문 없이 일단 모든 클릭을 다 수집하려 할 때
- 개인정보나 민감 데이터를 그대로 실어 보내려 할 때
- 이벤트 이름과 속성 체계가 정리되지 않은 상태에서 급하게 붙일 때

<Callout type="tip" title="이벤트는 제품 질문에서 시작해야 합니다">
무엇을 알고 싶은지 먼저 정하면 어떤 이벤트와 속성이 필요한지 자연스럽게 정리됩니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="분석 이벤트 좀 넣어주세요."
  goodPrompt="회원가입 퍼널에서 어느 단계에서 이탈하는지 알 수 있게 화면 진입, 입력 완료, 제출 성공, 제출 실패 이벤트를 정의해주세요. 이벤트 이름과 속성은 일관된 규칙으로 정리하고 개인정보는 제외해주세요."
/>

## 더 좋은 요청으로 바꾸는 방법

이벤트 트래킹을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 제품 질문에 답하고 싶은지
- 어떤 행동을 이벤트로 볼지
- 이벤트에 어떤 속성을 붙일지
- 개인정보나 민감 정보 제외 기준이 있는지

<PromptCodeBlock>
문서 검색 기능의 이벤트 트래킹을 설계해주세요.
검색창 포커스, 검색 실행, 결과 클릭, 결과 없음, 필터 변경 이벤트를 정의하고,
검색어 원문은 저장할지 여부를 신중히 검토해주세요.
이벤트 이름 규칙과 속성 표도 같이 제안해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
회원가입 퍼널 분석용 이벤트를 정리해주세요.
화면 진입, 입력 완료, 제출 클릭, 성공, 실패 이벤트를 설계하고,
실패 시 어떤 검증 단계에서 막혔는지 속성으로 남길 수 있게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
구독 업그레이드 흐름의 이벤트를 정의해주세요.
가격표 노출, 요금제 선택, 결제 진입, 결제 성공, 결제 실패, 재시도 클릭 이벤트를 포함하고,
분석 대시보드에서 퍼널 전환율을 계산하기 쉬운 형태로 설계해주세요.
</PromptCodeBlock>

<Callout type="warning" title="측정 가능성과 프라이버시는 같이 봐야 합니다">
분석 가치가 높아도 개인정보나 민감 정보가 그대로 들어가면 안 됩니다. 필요한 최소 정보만 이벤트 속성에 넣어야 합니다.
</Callout>

## 구현 체크리스트

- 제품 질문과 이벤트가 연결되어 있는가
- 이벤트 이름 규칙이 일관적인가
- 속성 정의가 명확한가
- 개인정보 제외 기준이 있는가
- 퍼널이나 KPI 계산에 실제로 쓸 수 있는가

## 자주 헷갈리는 개념 비교

### 이벤트 트래킹 vs 로깅

- 이벤트 트래킹은 제품 분석 목적입니다.
- 로깅은 운영과 디버깅 목적입니다.

### 이벤트 트래킹 vs KPI

- 이벤트는 원재료입니다.
- KPI는 그 이벤트를 집계해 만든 핵심 지표입니다.

### 이벤트 트래킹 vs 퍼널

- 이벤트는 개별 행동 단위입니다.
- 퍼널은 그 행동들이 이어지는 단계 구조입니다.
