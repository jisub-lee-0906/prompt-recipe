# 모달

> 한 줄 정의: 모달은 사용자의 현재 흐름을 잠시 멈추고, 확인이나 입력 같은 중요한 상호작용을 우선 처리하게 만드는 UI입니다.

## 왜 중요한가

기획자나 디자이너가 AI IDE에게 "확인 창", "팝업", "작은 창"이라고만 요청하면, 단순 박스 하나를 띄우는 수준으로 구현될 가능성이 높습니다. 하지만 실무에서 모달은 배경 dim, 닫기 규칙, 포커스 이동, 키보드 접근성까지 함께 포함하는 패턴입니다.

즉, "모달"이라는 단어를 정확하게 써야 AI IDE도 단순 시각 요소가 아니라 완전한 상호작용 패턴으로 이해합니다.

## 언제 쓰는가

모달은 아래처럼 현재 맥락보다 우선순위가 높은 짧은 상호작용에 적합합니다.

- 삭제나 탈퇴처럼 되돌리기 어려운 행동을 다시 확인할 때
- 간단한 이름 입력이나 옵션 선택을 즉시 받아야 할 때
- 사용자가 반드시 읽어야 하는 경고를 짧게 전달할 때

## 언제 쓰지 말아야 하는가

모달은 모든 보조 정보를 담는 용도로 쓰면 안 됩니다.

- 긴 설명문이나 도움말은 별도 페이지나 인라인 영역이 더 적합합니다.
- 단순 성공 메시지는 [토스트](/docs/ui-ux/toast)가 더 자연스럽습니다.
- 메뉴나 보조 패널은 [드로어](/docs/ui-ux/drawer)가 더 적합할 수 있습니다.

<Callout type="warning" title="모달은 자주보다 정확하게 써야 합니다">
모든 행동을 모달로 감싸면 사용자는 흐름이 자주 끊기고, 정말 중요한 경고도 무뎌집니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

비개발자가 AI IDE에게 자주 하는 요청은 보통 이런 식입니다.

- "삭제 전에 팝업 하나 띄워줘."
- "설정 누르면 작은 창 뜨게 해줘."
- "경고창처럼 보이게 해줘."

이 요청들은 모달의 구조적 요구사항이 빠져 있습니다. AI IDE는 배경 dim, ESC 닫기, 포커스 이동, 버튼 우선순위를 추론해야 하므로 결과가 흔들릴 수 있습니다.

## 더 좋은 요청으로 바꾸는 방법

좋은 요청은 아래 요소를 포함합니다.

- 언제 열리는지
- 제목과 본문 문구
- 버튼 종류와 우선순위
- 닫히는 규칙
- 위험 액션인지 여부

## 복붙 가능한 프롬프트

### 1. 삭제 확인용 모달

<PromptCodeBlock>
사용자 프로필 삭제 버튼을 누르면 중앙에 확인 모달이 열리게 해주세요.
제목은 "정말 삭제할까요?"로 표시하고, 본문에는 삭제 후 복구할 수 없다는 경고 문구를 넣어주세요.
취소 버튼과 삭제 버튼을 분리하고, 삭제 버튼은 더 위험해 보이도록 강조 스타일로 처리해주세요.
ESC 키와 바깥 영역 클릭으로 닫히는지 여부도 옵션으로 제어할 수 있게 해주세요.
</PromptCodeBlock>

### 2. 간단한 입력용 모달

<PromptCodeBlock>
새 폴더 만들기 버튼을 누르면 입력 모달이 열리게 해주세요.
제목은 "새 폴더 만들기"로 표시하고, 폴더 이름 입력창과 취소/생성 버튼을 배치해주세요.
입력값이 비어 있으면 생성 버튼을 비활성화하고, 생성 성공 후에는 모달이 닫히게 해주세요.
</PromptCodeBlock>

<Callout type="tip" title="입력 필드가 많아지면 모달보다 별도 페이지가 낫습니다">
모달은 짧은 흐름에 적합합니다. 여러 단계 입력이나 긴 설명이 들어가면 사용성이 급격히 떨어집니다.
</Callout>

## 구현 체크리스트

- 배경이 dim 처리되어 현재 흐름이 잠시 멈춘다는 것이 명확한가
- 키보드 포커스가 모달 안에 머무는가
- ESC, 닫기 버튼, 바깥 영역 클릭 규칙이 명확한가
- 위험 액션 버튼이 시각적으로 충분히 구분되는가
- 모바일에서도 너무 작거나 꽉 차지 않는가

## 자주 헷갈리는 개념 비교

### 모달 vs 드로어

- 모달: 사용자의 결정을 잠시 멈추게 하는 데 초점
- 드로어: 현재 흐름을 유지한 채 보조 패널을 열어 보여주는 데 초점

### 모달 vs 토스트

- 모달: 사용자의 추가 행동이 필요함
- 토스트: 결과만 짧게 알려주면 됨

### 모달 vs 다이얼로그

- 실무에서는 거의 비슷하게 쓰이지만, 다이얼로그는 특히 확인/입력 목적의 대화 구조를 강조할 때 자주 사용됩니다.
