# 인피니트 스크롤 UI

> 한 줄 정의: 인피니트 스크롤 UI는 사용자가 스크롤을 내릴수록 다음 결과를 계속 이어 붙여 보여주는 탐색 패턴입니다.

## 왜 중요한가

페이지네이션은 위치 기억에 강하고, 인피니트 스크롤은 연속 소비 경험에 강합니다. 둘은 전혀 다른 UX입니다. AI IDE에게 "아래로 계속 보이게 해줘"라고 하는 것보다 인피니트 스크롤 UI라고 말해야 로딩 방식, 끝 도달 처리, 스크롤 복원 같은 세부가 같이 설계됩니다.

## 언제 쓰는가

- 피드, 갤러리, 콘텐츠 탐색처럼 연속 소비가 중요한 화면에서
- 사용자가 많은 결과를 자연스럽게 이어서 보게 하고 싶을 때
- 페이지 번호보다 흐름 유지가 더 중요한 경우

## 언제 쓰지 말아야 하는가

- 특정 위치를 기억하고 다시 돌아와야 하는 목록일 때
- 결과 수가 많아도 구간 공유나 페이지 단위 접근이 중요할 때
- 스크롤 끝에서 계속 불러오는 경험이 피로를 줄 가능성이 클 때

<Callout type="tip" title="인피니트 스크롤은 끝 처리와 복귀 경험이 중요합니다">
계속 붙는 것만 생각하기 쉽지만, 로딩 중 표시, 더 이상 결과가 없을 때의 메시지, 뒤로 가기 후 스크롤 복원이 같이 설계되어야 합니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

인피니트 스크롤을 요청할 때는 아래를 같이 말해야 합니다.

- 언제 다음 결과를 불러올지
- 로딩 중 어떤 UI를 보여줄지
- 끝에 도달했을 때 무엇을 보여줄지
- 뒤로 가기 후 스크롤 위치 복원이 필요한지

<PromptCodeBlock>
문서 탐색 화면을 인피니트 스크롤 UI로 바꿔주세요.
사용자가 하단 근처에 도달하면 다음 문서 카드가 자동으로 로드되고, 로딩 중에는 스켈레톤 카드를 보여주세요.
더 이상 결과가 없으면 끝 메시지를 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 결과 목록을 인피니트 스크롤 방식으로 보여주세요.
필터와 정렬은 상단에 유지하고, 하단 근처로 오면 다음 결과를 이어서 붙여주세요.
뒤로 가기 후에는 가능하면 이전 스크롤 위치와 로드된 결과가 유지되게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
모바일 피드 화면에 인피니트 스크롤을 적용해주세요.
네트워크가 느릴 때는 하단 로딩 표시를 충분히 보여주고, 너무 빠르게 여러 번 요청되지 않게 방지 로직도 고려해주세요.
</PromptCodeBlock>

<Callout type="warning" title="인피니트 스크롤은 항상 페이지네이션보다 좋은 것이 아닙니다">
연속 소비에는 좋지만, 특정 위치 재방문과 결과 공유에는 약할 수 있습니다. 탐색 목적에 맞는지 먼저 판단해야 합니다.
</Callout>

## 구현 체크리스트

- 다음 결과 로드 시점이 자연스러운가
- 로딩 중 스켈레톤이나 진행 표시가 있는가
- 끝에 도달했을 때 상태가 분명한가
- 중복 요청 방지가 있는가
- 뒤로 가기나 재방문 경험을 고려했는가

## 자주 헷갈리는 개념 비교

### 인피니트 스크롤 UI vs 페이지네이션

- 인피니트 스크롤은 연속 소비 경험에 강합니다.
- 페이지네이션은 위치 기억과 재방문에 강합니다.

### 인피니트 스크롤 UI vs 더 보기 버튼

- 인피니트 스크롤은 자동으로 이어 붙입니다.
- 더 보기 버튼은 사용자가 명시적으로 다음 결과를 요청합니다.

### 인피니트 스크롤 UI vs 무한 스크롤 구현

- 인피니트 스크롤 UI는 사용자 경험 패턴입니다.
- 무한 스크롤 구현은 이를 코드로 만드는 기술적 방식입니다.
