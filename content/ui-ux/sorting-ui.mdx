# 정렬 UI

> 한 줄 정의: 정렬 UI는 같은 결과 집합을 어떤 기준과 순서로 보여줄지 바꾸는 인터페이스입니다.

## 왜 중요한가

필터가 무엇을 보여줄지 정한다면, 정렬은 어떤 순서로 보여줄지 정합니다. 사용자 입장에서는 둘이 전혀 다른 기능인데, 요청이 모호하면 쉽게 섞여버립니다. AI IDE에게 "필터도 넣고 정렬도 넣어줘"가 아니라 정렬 UI를 별도로 지정해야 순서 기준과 기본 정렬이 명확해집니다.

## 언제 쓰는가

- 검색 결과나 목록을 최신순, 인기순, 가나다순 등으로 바꿔볼 때
- 문서나 상품 목록에서 기본 순서를 사용자에게 바꾸게 할 때
- 관리자 화면에서 테이블 열 기준 정렬이 필요할 때

## 언제 쓰지 말아야 하는가

- 정렬 기준이 사실상 하나뿐이라 바꿀 의미가 없을 때
- 필터와 정렬을 한 UI 안에 무리하게 섞어 사용자가 혼란스러워질 때

<Callout type="tip" title="정렬은 기본값이 특히 중요합니다">
사용자가 직접 바꾸기 전까지 어떤 기준으로 보여줄지 먼저 정해야 합니다. 정렬 기준이 불분명하면 같은 데이터도 제각각 보일 수 있습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

정렬 UI를 요청할 때는 아래를 같이 말해야 합니다.

- 기본 정렬 기준이 무엇인지
- 사용 가능한 정렬 옵션이 무엇인지
- 필터 바와 함께 보여줄지
- URL 상태나 쿼리와 연결할지

<PromptCodeBlock>
문서 목록 상단에 정렬 UI를 추가해주세요.
기본값은 최신 수정순으로 두고, 사용자가 `최신순`, `제목순`, `인기순` 중 하나를 선택할 수 있게 해주세요.
현재 선택된 정렬 기준이 분명히 보여야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
검색 결과 화면에서 필터 바 옆에 정렬 드롭다운을 넣어주세요.
기본값은 관련도순이고, 사용자가 최신순과 제목순으로도 바꿀 수 있게 해주세요.
정렬이 바뀌면 URL 쿼리에도 반영해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 테이블에서는 열 헤더 클릭으로 정렬 가능하게 해주세요.
현재 어떤 열이 오름차순인지 내림차순인지 아이콘으로 보여주고, 다른 열로 바꾸면 기존 정렬 상태는 해제해주세요.
</PromptCodeBlock>

<Callout type="warning" title="정렬과 필터를 같은 개념처럼 다루면 안 됩니다">
정렬은 같은 결과의 순서를 바꾸고, 필터는 결과 범위를 줄입니다. 둘이 섞이면 사용자가 왜 목록이 바뀌는지 이해하기 어려워집니다.
</Callout>

## 구현 체크리스트

- 기본 정렬 기준이 정의되어 있는가
- 현재 선택된 정렬 상태가 보이는가
- 필터와 역할이 구분되는가
- URL이나 상태와 자연스럽게 연결되는가
- 모바일에서도 바꾸기 쉬운가

## 자주 헷갈리는 개념 비교

### 정렬 UI vs 필터 바

- 정렬 UI는 같은 결과의 순서를 바꿉니다.
- 필터 바는 결과 집합을 줄입니다.

### 정렬 UI vs 페이지네이션

- 정렬 UI는 순서를 바꿉니다.
- 페이지네이션은 결과를 여러 페이지로 나눕니다.

### 정렬 UI vs 검색 바

- 정렬 UI는 이미 나온 결과의 순서를 바꿉니다.
- 검색 바는 어떤 결과를 찾을지 결정합니다.
