# 폴백

> 한 줄 정의: 폴백은 원래 의도한 동작이나 콘텐츠가 실패했을 때 대신 보여주거나 실행할 대체 경로입니다.

## 왜 중요한가

실패 시나리오를 전부 막을 수는 없습니다. 대신 사용자가 완전히 막히지 않도록 대체 경로를 준비할 수 있습니다. AI IDE에게 "안 되면 다른 걸 보여줘"보다 폴백 전략이라고 말해야 어떤 상황에서 어떤 대안을 제공할지 더 명확하게 설계됩니다.

## 언제 쓰는가

- 이미지, 외부 데이터, 추천 결과처럼 실패 가능성이 있는 콘텐츠에서
- 새 기능이 실패했을 때 기존 기능으로 되돌아가야 할 때
- 네트워크나 권한 문제로 기본 경로가 막혔을 때

## 언제 쓰지 말아야 하는가

- 실패 사실을 숨기기만 하고 문제를 더 알아차리기 어렵게 만들 때
- 원래 경로보다 폴백이 더 자주 보이게 방치할 때
- 대체 경로가 실제로는 동작하지 않는데 안심용으로만 붙일 때

<Callout type="tip" title="폴백은 실패를 감추는 것이 아니라 사용자를 덜 막히게 하는 장치입니다">
실패를 투명하게 다루되, 사용자가 다음 행동을 이어갈 수 있게 만드는 것이 핵심입니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

  badPrompt="안 되면 다른 화면 보여주세요."

## 더 좋은 요청으로 바꾸는 방법

폴백을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 기본 경로가 실패할 수 있는지
- 어떤 대체 경로가 있는지
- 사용자에게 실패를 얼마나 드러낼지
- 기능 플래그나 실패 시나리오와 연결되는지

<PromptCodeBlock>
새 검색 모달 기능이 비활성화되거나 실패하면 기존 검색 바로 자연스럽게 폴백되게 해주세요.
사용자는 기능이 깨졌다는 느낌 없이 계속 검색할 수 있어야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
문서 썸네일 이미지 로드에 실패하면 기본 플레이스홀더 이미지를 보여주세요.
레이아웃이 깨지지 않게 하고, 텍스트 정보는 계속 읽을 수 있게 유지해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
외부 추천 API가 실패하면 기본 추천 문서 목록으로 폴백되게 해주세요.
완전히 빈 화면이 되지 않게 하고, 필요하면 조용한 안내 문구만 추가해주세요.
</PromptCodeBlock>

<Callout type="warning" title="폴백이 기본 경로를 대체하는 수준으로 자주 보이면 근본 문제를 놓칠 수 있습니다">
대체 경로가 있다고 해서 실패 원인을 방치하면 안 됩니다. 폴백은 임시 안전장치이지 최종 해결책이 아닙니다.
</Callout>

## 구현 체크리스트

- 어떤 실패에서 폴백이 발동되는가
- 대체 경로가 실제로 유효한가
- 사용자가 완전히 막히지 않는가
- 실패 원인 추적은 별도로 가능한가
- 기본 경로와 폴백 경로가 혼동되지 않는가

## 자주 헷갈리는 개념 비교

### 폴백 vs 실패 시나리오

- 폴백은 대체 경로 자체입니다.
- 실패 시나리오는 실패 경험 전체 설계입니다.

### 폴백 vs 기능 플래그

- 폴백은 실패 시 다른 경로로 전환합니다.
- 기능 플래그는 노출 여부를 제어합니다.

### 폴백 vs 재시도

- 폴백은 다른 경로로 갑니다.
- 재시도는 같은 경로를 다시 시도합니다.
