# 빈 상태

> 한 줄 정의: 빈 상태는 보여줄 데이터가 없을 때 사용자가 막히지 않도록 현재 이유와 다음 행동을 안내하는 UI입니다.

## 왜 중요한가

비어 있는 화면은 정보가 없는 상태가 아니라, 설명이 빠진 상태입니다. AI IDE에게 "아무 것도 없을 때 안내 좀 넣어줘"라고 하는 것보다 빈 상태라고 정확히 지정하면 제목, 설명, 행동 버튼, 일러스트, 초기 진입 문맥까지 더 적절하게 설계할 수 있습니다.

## 언제 쓰는가

- 즐겨찾기, 알림, 프로젝트 목록처럼 처음엔 비어 있을 수 있는 화면
- 검색 결과가 없을 때
- 필터를 너무 좁게 걸어 결과가 0건일 때

## 언제 쓰지 말아야 하는가

- 실제로는 로딩 중인데 데이터가 없는 것처럼 보이면 안 될 때
- 서버 오류나 권한 문제처럼 실패 상태를 별도로 설명해야 할 때
- 한 줄 메시지보다 바로 생성 폼을 보여주는 편이 더 자연스러운 첫 진입 화면일 때

<Callout type="tip" title="좋은 빈 상태는 다음 행동을 반드시 제시합니다">
사용자가 무엇을 하면 이 화면을 벗어날 수 있는지 보여줘야 합니다. 단순히 "데이터가 없습니다"로 끝나면 정보는 전달했지만 경험은 멈춥니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="비어 있으면 안내 문구 하나 넣어주세요."

/>

## 더 좋은 요청으로 바꾸는 방법

빈 상태를 요청할 때는 아래를 함께 말해야 합니다.

- 왜 비어 있는 상태인지
- 사용자에게 어떤 행동을 유도할지
- 첫 진입인지, 검색 결과 없음인지, 필터 결과 없음인지
- 일러스트나 아이콘이 필요한지

<PromptCodeBlock>
즐겨찾기 목록이 비어 있을 때 보여줄 빈 상태 UI를 만들어주세요.
제목, 짧은 설명, 그리고 `문서 둘러보기` 버튼을 넣어 사용자가 다음 행동을 바로 할 수 있게 해주세요.
화면이 너무 허전하지 않게 간단한 북마크 아이콘도 함께 배치해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 결과가 없을 때의 빈 상태를 만들어주세요.
사용자가 입력한 검색어를 문구 안에 포함하고, `검색어를 다시 입력해보세요` 같은 설명과 함께 `필터 초기화` 버튼을 제공해주세요.
이 상태는 오류가 아니라 결과 없음이라는 점이 분명히 드러나야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
프로젝트가 하나도 없는 첫 진입 화면에 빈 상태를 넣어주세요.
`첫 프로젝트를 만들어보세요` 같은 제목과 설명을 넣고, 가장 중요한 CTA는 `프로젝트 만들기`로 배치해주세요.
관리자용 복잡한 설명보다 처음 쓰는 사람도 이해할 수 있는 문구를 사용해주세요.
</PromptCodeBlock>

<Callout type="warning" title="빈 상태와 에러 상태는 다릅니다">
데이터가 없는 것과 데이터를 가져오지 못한 것은 다른 문제입니다. 둘을 같은 화면으로 처리하면 사용자는 지금 무엇을 해야 하는지 판단하기 어려워집니다.
</Callout>

## 구현 체크리스트

- 왜 비어 있는지 설명이 되는가
- 다음 행동 버튼이 명확하게 보이는가
- 오류 상태와 시각적으로 구분되는가
- 첫 진입과 검색 결과 없음 상황을 구분하는가
- 문구가 지나치게 건조하거나 탓하는 느낌이 없는가

## 자주 헷갈리는 개념 비교

### 빈 상태 vs 에러 상태

- 빈 상태는 결과가 없는 정상 상황입니다.
- 에러 상태는 문제가 발생한 비정상 상황입니다.

### 빈 상태 vs 로딩 상태

- 빈 상태는 현재 결과가 0개인 상태입니다.
- 로딩 상태는 아직 결과를 가져오는 중인 상태입니다.

### 빈 상태 vs 온보딩

- 빈 상태는 현재 데이터 부재를 설명합니다.
- 온보딩은 사용법과 초기 진입 흐름 전체를 설계합니다.
