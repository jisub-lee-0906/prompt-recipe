# 커맨드 팔레트

> 한 줄 정의: 커맨드 팔레트는 검색과 빠른 이동, 명령 실행을 하나의 키보드 중심 인터페이스로 묶은 패턴입니다.

## 왜 중요한가

검색 바가 주로 콘텐츠 찾기에 집중한다면, 커맨드 팔레트는 검색과 명령 실행까지 함께 다룹니다. AI IDE에게 "Cmd+K 검색창"이라고만 하면 단순 검색 입력으로 끝날 수 있지만, 커맨드 팔레트라고 지정하면 단축키, 결과 이동, 섹션 구분까지 더 구조적으로 설계됩니다.

## 언제 쓰는가

- 문서 검색과 빠른 이동을 한 번에 제공하고 싶을 때
- 키보드 중심 사용성을 높이고 싶을 때
- 검색 외에 `홈으로 이동`, `테마 전환` 같은 빠른 명령도 넣고 싶을 때

## 언제 쓰지 말아야 하는가

- 검색 대상이 매우 적고 단순한 입력창이면 충분할 때
- 키보드 탐색보다 시각적 네비게이션이 더 중요한 서비스일 때
- 명령이 거의 없는데 과한 구조만 추가될 때

<Callout type="tip" title="커맨드 팔레트는 검색과 행동을 함께 다룰 때 강합니다">
문서 찾기, 카테고리 이동, 설정 열기 같은 액션이 한 자리에 모이면 탐색 속도가 크게 좋아집니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

커맨드 팔레트를 요청할 때는 아래를 같이 말해야 합니다.

- 검색만 할지 명령도 넣을지
- 어떤 섹션으로 결과를 나눌지
- 단축키와 키보드 이동을 지원할지
- 선택 후 어디로 이동하거나 무엇을 실행할지

<PromptCodeBlock>
Cmd/Ctrl+K로 열리는 커맨드 팔레트를 만들어주세요.
문서 제목·설명·태그로 검색할 수 있어야 하고, 결과는 `문서`, `이동`, `동작` 섹션으로 나눠 보여주세요.
키보드로 항목 이동과 선택이 가능해야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
문서 사이트 커맨드 팔레트에 빠른 이동 항목도 넣어주세요.
`홈`, `UI/UX`, `프론트엔드`, `백엔드` 카테고리 이동과 `다크 모드 전환` 같은 즉시 실행 동작을 함께 보여주세요.
검색어가 없을 때는 추천 항목을 먼저 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
커맨드 팔레트가 열려 있을 때 ESC로 닫히고, Enter로 선택되며, 방향키로 결과를 이동할 수 있게 해주세요.
선택된 항목은 시각적으로 분명히 강조해주세요.
</PromptCodeBlock>

<Callout type="warning" title="커맨드 팔레트는 입력창만 만들고 끝내면 반쪽짜리입니다">
단축키, 키보드 이동, 결과 분류, 선택 후 행동이 함께 있어야 실제로 커맨드 팔레트처럼 느껴집니다.
</Callout>

## 구현 체크리스트

- Cmd/Ctrl+K로 열리는가
- 키보드만으로 탐색과 선택이 가능한가
- 결과가 의미 있는 섹션으로 나뉘는가
- 검색 결과와 명령 실행이 역할 충돌 없이 정리되는가
- 결과 없음 상태도 자연스럽게 처리되는가

## 자주 헷갈리는 개념 비교

### 커맨드 팔레트 vs 검색 바

- 커맨드 팔레트는 검색과 명령 실행을 함께 다룹니다.
- 검색 바는 주로 콘텐츠 탐색에 집중합니다.

### 커맨드 팔레트 vs 컨텍스트 메뉴

- 커맨드 팔레트는 전역 검색과 전역 동작에 가깝습니다.
- 컨텍스트 메뉴는 특정 항목 문맥에 붙는 액션 메뉴입니다.

### 커맨드 팔레트 vs 시트

- 커맨드 팔레트는 키보드 중심 검색 오버레이입니다.
- 시트는 측면 패널 중심 보조 UI입니다.
