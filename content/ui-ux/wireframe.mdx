# 와이어프레임

> 한 줄 정의: 와이어프레임은 색상과 디테일보다 화면 구조와 정보 우선순위를 먼저 확인하기 위한 저해상도 설계 초안입니다.

## 왜 중요한가

처음부터 예쁜 화면을 요구하면 구조가 흔들린 상태에서 시각 요소만 커지는 경우가 많습니다. 와이어프레임을 먼저 만들면 어떤 정보가 어디에 있어야 하는지, 어떤 액션이 먼저 보여야 하는지 빠르게 합의할 수 있습니다. AI IDE에게도 바로 완성본을 요구하기보다 와이어프레임부터 시키는 편이 훨씬 효율적입니다.

## 언제 쓰는가

- 새 기능 화면의 구조를 처음 잡을 때
- 대시보드, 설정, 문서 목록처럼 섹션이 많은 화면을 정리할 때
- 여러 역할이 빠르게 구조 합의를 해야 할 때

## 언제 쓰지 말아야 하는가

- 이미 구조가 명확하고 현재는 시각 디자인 디테일만 다듬는 단계일 때
- 단순 컴포넌트 하나의 스타일 조정이 목적일 때

<Callout type="tip" title="와이어프레임은 예쁘게 만드는 문서가 아닙니다">
핵심은 구조, 정보 우선순위, 주요 액션 위치입니다. 색상과 장식보다 어떤 영역이 먼저 보이고 어떤 요소가 묶여야 하는지 확인하는 데 집중해야 합니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

와이어프레임을 요청할 때는 아래를 같이 말해야 합니다.

- 화면의 목표가 무엇인지
- 필수 섹션이 무엇인지
- 가장 먼저 보여야 하는 정보가 무엇인지
- 데스크톱과 모바일 구조 차이가 있는지

<PromptCodeBlock>
관리자 문서 대시보드의 와이어프레임을 설계해주세요.
상단에는 검색과 필터, 중앙에는 문서 리스트, 오른쪽에는 최근 수정 활동을 배치하고, 시각 스타일보다 영역 구조와 정보 우선순위가 먼저 보이게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
설정 페이지의 와이어프레임을 만들어주세요.
왼쪽에는 섹션 메뉴, 오른쪽에는 현재 설정 본문이 보이게 하고, 상단에는 페이지 제목과 저장 상태를 배치해주세요.
모바일에서는 왼쪽 메뉴가 상단 탭이나 드롭다운으로 바뀌는 구조도 함께 고려해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
서비스 랜딩 페이지의 와이어프레임을 그려주세요.
히어로 섹션, 핵심 기능 소개, 사용 예시, 마지막 CTA 영역이 순서대로 보이게 해주세요.
문구 디테일보다는 섹션 구조와 스크롤 흐름이 먼저 드러나는 형태로 만들어주세요.
</PromptCodeBlock>

<Callout type="warning" title="와이어프레임 단계에서 비주얼 디테일에 너무 빨리 들어가면 구조 검토가 흐려집니다">
색상, 일러스트, 애니메이션 논의는 이후 단계로 미루는 편이 좋습니다. 먼저 구조가 맞는지 확인한 뒤 스타일을 입혀야 재작업이 줄어듭니다.
</Callout>

## 구현 체크리스트

- 화면 목표가 명확한가
- 필수 섹션이 빠지지 않았는가
- 정보 우선순위가 배치에 반영되었는가
- 모바일과 데스크톱 구조 차이가 고려되었는가
- 스타일보다 구조 검토가 우선되는가

## 자주 헷갈리는 개념 비교

### 와이어프레임 vs 최종 디자인

- 와이어프레임은 구조와 배치 중심입니다.
- 최종 디자인은 색상, 타이포, 시각 디테일까지 포함합니다.

### 와이어프레임 vs 사용자 흐름

- 와이어프레임은 개별 화면 구조를 다룹니다.
- 사용자 흐름은 여러 화면 사이의 이동 경로를 다룹니다.

### 와이어프레임 vs 레이아웃

- 와이어프레임은 설계 초안입니다.
- 레이아웃은 실제 구현된 구조 패턴입니다.
