# 드로어

> 한 줄 정의: 드로어는 화면 가장자리에서 밀려 나와 메뉴나 보조 정보를 현재 화면 흐름 안에서 보여주는 패널형 UI입니다.

## 왜 중요한가

AI IDE에게 "옆에서 패널 나오게 해줘"라고 요청하면 단순 absolute 박스가 뜨는 수준으로 끝나기 쉽습니다. 하지만 실제 드로어는 열리는 방향, 배경 dim, 닫힘 규칙, 모바일 너비, 내부 스크롤까지 포함하는 패턴입니다.

드로어는 현재 화면을 완전히 끊지 않고 보조 작업이나 보조 탐색을 여는 데 강합니다.

## 언제 쓰는가

- 모바일 햄버거 메뉴
- 필터 패널이나 조건 선택 패널
- 장바구니 요약, 상세 설정 같은 보조 정보

## 언제 쓰지 말아야 하는가

- 사용자의 결정을 잠시 멈춰 세워야 하는 경고 상황
- 짧은 결과 메시지만 보여주면 되는 경우
- 여러 단계 입력을 처리해야 하는 복잡한 폼

<Callout type="tip" title="드로어는 현재 흐름을 유지한 채 보조 패널을 여는 데 적합합니다">
메인 화면을 완전히 끊지 않으면서 메뉴, 필터, 요약 정보를 잠깐 보여줘야 할 때 가장 자연스럽습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "메뉴가 옆에서 나오게 해줘"
- "필터를 열어볼 수 있게 해줘"
- "작은 패널로 보여줘"

이 요청에는 어느 방향에서 열리는지, 닫는 규칙이 무엇인지, 모바일 전용인지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 왼쪽/오른쪽/아래 중 열리는 방향을 정하기
- 바깥 클릭, ESC, 닫기 버튼 규칙을 적기
- 내부 콘텐츠 길이가 길 때 스크롤 처리도 넣기
- 모바일과 데스크톱 노출 방식을 함께 정하기

  badPrompt="메뉴가 옆에서 나오게 해줘."
  goodPrompt="모바일 화면에서 햄버거 버튼을 누르면 왼쪽에서 드로어가 열리게 해주세요. 배경은 어둡게 dim 처리하고, 바깥 영역을 누르거나 닫기 버튼을 누르면 닫히게 해주세요. 현재 선택된 메뉴는 강조 스타일로 보여주세요."
/>

## 복붙 가능한 프롬프트 예시

### 1. 모바일 내비게이션 드로어

<PromptCodeBlock>
모바일 화면에서 햄버거 버튼을 누르면 왼쪽에서 드로어가 열리게 해주세요.
배경은 어둡게 dim 처리하고, 바깥 영역을 누르거나 닫기 버튼을 누르면 닫히게 해주세요.
현재 선택된 메뉴는 강조 스타일로 보여주고, 메뉴를 누르면 드로어가 자동으로 닫히게 해주세요.
</PromptCodeBlock>

### 2. 필터 드로어

<PromptCodeBlock>
문서 목록 페이지 오른쪽에서 필터 드로어가 열리게 해주세요.
카테고리, 태그, 난이도 필터를 넣고, 적용 버튼과 초기화 버튼을 함께 배치해주세요.
내부 콘텐츠가 길어질 경우 드로어 안에서만 스크롤되게 해주세요.
</PromptCodeBlock>

### 3. 장바구니 요약 드로어

<PromptCodeBlock>
상품 상세 페이지에서 장바구니 담기 버튼을 누르면 오른쪽 드로어가 열리게 해주세요.
드로어 안에는 담은 상품 요약, 수량, 결제 버튼을 보여주고, 사용자가 현재 상품 페이지를 떠나지 않게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="드로어 안 정보가 너무 많아지면 별도 페이지가 더 낫습니다">
보조 패널 수준을 넘어서 긴 설명이나 복잡한 폼이 들어가면 사용성이 급격히 떨어집니다.
</Callout>

## 구현 체크리스트

- 열리는 방향이 명확한가
- 배경 dim과 닫힘 규칙이 있는가
- 내부 스크롤 처리가 되는가
- 모바일과 데스크톱에서 역할이 구분되는가
- 현재 선택 상태가 자연스럽게 보이는가

## 자주 헷갈리는 개념 비교

### 드로어 vs 모달

- 드로어: 현재 흐름을 유지한 채 보조 패널을 연다
- 모달: 현재 흐름을 잠시 멈추고 집중시킨다

### 드로어 vs 사이드바

- 드로어: 필요할 때만 열리고 닫힌다
- 사이드바: 계속 고정되어 보인다

### 드로어 vs 팝오버

- 드로어: 더 큰 영역의 보조 패널
- 팝오버: 특정 요소 근처의 작은 보조 패널
