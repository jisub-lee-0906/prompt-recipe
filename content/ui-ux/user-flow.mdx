# 사용자 흐름

> 한 줄 정의: 사용자 흐름은 사용자가 특정 목표를 이루기 위해 어떤 화면과 행동을 순서대로 거치는지 설계한 경로입니다.

## 왜 중요한가

AI IDE에게 화면 하나만 설명하면, 그 화면이 앞뒤 맥락 속에서 어떻게 연결되는지는 빠지기 쉽습니다. 사용자 흐름을 먼저 정리하면 로그인, 가입, 검색, 결제처럼 여러 화면이 이어지는 기능을 더 일관되게 설계할 수 있습니다.

## 언제 쓰는가

- 회원가입, 로그인, 결제처럼 여러 단계로 이어지는 기능을 설계할 때
- 정상 경로뿐 아니라 실패, 취소, 뒤로 가기 흐름까지 정리해야 할 때
- 기능 요구사항을 화면 단위가 아니라 서비스 경험 단위로 설명하고 싶을 때

## 언제 쓰지 말아야 하는가

- 단일 버튼 클릭 후 즉시 끝나는 미세 인터랙션만 다룰 때
- 이미 구조가 완전히 확정돼 있고 현재는 세부 UI만 다듬는 단계일 때

<Callout type="tip" title="흐름을 먼저 적으면 AI IDE가 화면을 연결해서 생각합니다">
`로그인 페이지를 만들어줘`보다 `비로그인 사용자가 로그인 후 대시보드로 들어가는 흐름을 만들어줘`가 훨씬 강한 요청입니다. 화면보다 경로가 먼저 잡히면 실패 시나리오도 자연스럽게 따라옵니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

사용자 흐름을 요청할 때는 아래를 같이 말해야 합니다.

- 사용자의 시작 상태가 무엇인지
- 성공 경로가 어떻게 이어지는지
- 실패, 취소, 뒤로 가기 같은 분기가 있는지
- 마지막 도착 지점이 어디인지

<PromptCodeBlock>
비로그인 사용자가 이메일로 회원가입을 시작하고, 인증을 마친 뒤 온보딩을 거쳐 첫 대시보드에 도착하는 사용자 흐름을 설계해주세요.
각 단계 화면과 실패 분기, 이전 단계로 돌아가는 흐름까지 함께 정리해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
로그인 사용자가 검색 바에서 문서를 검색하고, 검색 결과를 필터링한 뒤 상세 문서를 열어 프롬프트를 복사하는 사용자 흐름을 설계해주세요.
검색 결과 없음, 네트워크 실패, 뒤로 가기 시 상태 유지까지 고려해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
사용자가 결제 화면에서 상품을 확인하고 결제 수단을 선택한 뒤 결제를 완료하거나 실패하는 흐름을 설계해주세요.
성공, 실패, 결제 취소, 중복 결제 방지까지 포함해서 화면 단위로 정리해주세요.
</PromptCodeBlock>

<Callout type="warning" title="정상 흐름만 만들면 실서비스와 멀어집니다">
실패, 취소, 만료, 뒤로 가기 같은 분기를 함께 적어야 실제 서비스 품질이 올라갑니다. 정상 흐름만 있는 설계는 데모로는 보여도 운영 단계에서 금방 구멍이 드러납니다.
</Callout>

## 구현 체크리스트

- 시작 상태와 종료 상태가 분명한가
- 단계별 화면이 순서대로 연결되는가
- 실패와 예외 분기가 포함되는가
- 완료 후 어디로 이동하는지 정의되어 있는가
- 뒤로 가기와 중간 이탈도 고려되었는가

## 자주 헷갈리는 개념 비교

### 사용자 흐름 vs 와이어프레임

- 사용자 흐름은 화면 사이의 이동 경로를 다룹니다.
- 와이어프레임은 개별 화면의 배치를 다룹니다.

### 사용자 흐름 vs 정보 구조

- 사용자 흐름은 목표 달성 경로를 설명합니다.
- 정보 구조는 콘텐츠와 화면의 분류 체계를 설명합니다.

### 사용자 흐름 vs 확인 흐름

- 사용자 흐름은 전체 서비스 단위의 경로입니다.
- 확인 흐름은 위험 행동 직전의 짧은 분기 설계입니다.
