# 툴팁

> 한 줄 정의: 툴팁은 사용자가 특정 요소를 가리키거나 포커스했을 때 짧은 보조 설명을 보여주는 힌트 UI입니다.

## 왜 중요한가

툴팁은 작은 공간으로 의미를 보완할 수 있어서 아이콘 중심 UI나 밀도가 높은 화면에서 자주 쓰입니다. 하지만 "설명 나오게 해줘" 정도로 요청하면 너무 긴 문장을 넣거나, 중요 정보를 툴팁에만 넣어버리는 식으로 잘못 구현되기 쉽습니다.

툴팁은 핵심 정보가 아니라 짧은 보조 설명에 적합합니다.

## 언제 쓰는가

- 아이콘 버튼의 의미를 짧게 보완할 때
- 약어, 전문 용어를 짧게 풀어줄 때
- 현재 맥락을 방해하지 않는 짧은 힌트가 필요할 때

## 언제 쓰지 말아야 하는가

- 길고 중요한 설명이 필요할 때
- 경고, 확인, 실패 안내처럼 사용자가 반드시 읽어야 할 때
- 모바일 중심 환경에서 툴팁만으로 정보 전달을 기대할 때

<Callout type="info" title="툴팁은 보조 정보이지 핵심 정보가 아닙니다">
툴팁이 없으면 이해할 수 없는 정보라면, 그 정보는 다른 방식으로 기본 노출하는 편이 더 좋습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "아이콘 위에 설명 보이게 해줘"
- "마우스 올리면 텍스트 뜨게 해줘"
- "용어 뜻 알려주는 작은 창 넣어줘"

이 요청에는 어느 요소에 붙는지, 어디에 위치하는지, 모바일에서는 어떻게 보일지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 요소에 붙는지 지정하기
- 툴팁 문구를 짧게 쓰기
- hover와 keyboard focus 모두 지원하도록 적기
- 화면 가장자리에서 위치 조정도 요구하기

<PromptCard
  badPrompt="아이콘 위에 설명 보이게 해줘."
  goodPrompt="상단 액션 바의 공유 아이콘 위에 마우스를 올리거나 키보드 포커스를 주면 '링크 복사'라는 툴팁이 뜨게 해주세요. 툴팁은 요소 바로 위에 배치하고, 화면 가장자리에서는 잘리지 않게 위치를 조정해주세요."
/>

## 복붙 가능한 프롬프트 예시

### 1. 아이콘 버튼 툴팁

<PromptCodeBlock>
상단 액션 바의 공유 아이콘 위에 마우스를 올리거나 키보드 포커스를 주면 "링크 복사"라는 툴팁이 뜨게 해주세요.
툴팁은 요소 바로 위에 배치하고, 화면 가장자리에서는 잘리지 않게 위치를 조정해주세요.
짧고 읽기 쉬운 문구만 보여주세요.
</PromptCodeBlock>

### 2. 용어 설명 툴팁

<PromptCodeBlock>
문서 본문에 있는 "SSG" 용어 옆에 정보 아이콘을 두고, 포커스나 hover 시 "정적 사이트 생성"이라는 툴팁이 뜨게 해주세요.
너무 긴 설명은 넣지 말고 한 줄 정의만 보여주세요.
</PromptCodeBlock>

### 3. 비활성 버튼 설명 툴팁

<PromptCodeBlock>
제출 버튼이 비활성화되어 있을 때 왜 비활성화됐는지 설명하는 툴팁을 붙여주세요.
예를 들어 필수 항목이 비어 있으면 "필수 입력을 먼저 완료해주세요"라는 짧은 문구를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="모바일에서는 툴팁 의존도가 낮아야 합니다">
hover가 없는 환경에서는 툴팁이 핵심 정보를 전달하는 수단이 되기 어렵기 때문에, 중요한 내용은 별도 문구나 구조로도 보여주는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- hover와 focus 모두 지원하는가
- 문구가 짧고 명확한가
- 화면 가장자리에서 잘리지 않는가
- 모바일에서도 핵심 정보가 사라지지 않는가
- 툴팁 없이도 주요 기능을 이해할 수 있는가

## 자주 헷갈리는 개념 비교

### 툴팁 vs 팝오버

- 툴팁: 짧은 설명만 보여준다
- 팝오버: 선택지나 상호작용이 들어간다

### 툴팁 vs 인라인 설명

- 툴팁: 필요할 때만 보이는 힌트
- 인라인 설명: 항상 노출되는 설명

### 툴팁 vs 토스트

- 툴팁: 사용자의 hover/focus에 반응하는 보조 설명
- 토스트: 어떤 작업의 결과를 짧게 알리는 메시지
