# 마이크로카피

> 한 줄 정의: 마이크로카피는 버튼, 라벨, 도움말, 오류 메시지처럼 짧지만 사용자의 이해와 행동을 직접 바꾸는 UI 문구입니다.

## 왜 중요한가

같은 기능도 문구가 모호하면 사용자는 무엇을 눌러야 하는지, 지금 어떤 상태인지, 실수했는지 알기 어렵습니다. AI IDE에게 "문구 좀 다듬어줘"라고만 말하면 분위기만 예쁜 텍스트가 나오기 쉽고, 실제 행동 유도나 오류 복구에는 약할 수 있습니다.

## 언제 쓰는가

- 버튼, 입력 도움말, 빈 상태, 오류 상태 문구를 설계할 때
- 위험한 행동 전 확인 문구를 명확히 해야 할 때
- 가입, 결제, 제출, 삭제처럼 사용자의 불안을 줄여야 할 때

## 언제 쓰지 말아야 하는가

- 화면 구조 문제를 문구만 늘려서 해결하려 할 때
- 너무 긴 설명으로 핵심 행동을 가릴 때
- 같은 의미를 여러 톤으로 섞어 일관성이 깨질 때

<Callout type="tip" title="좋은 문구는 다음 행동을 분명히 알려줍니다">
설명만 하는 문구보다 지금 무엇을 해야 하는지, 실패했다면 어떻게 복구하는지 알려주는 문구가 더 유용합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="문구를 좀 더 자연스럽게 바꿔주세요."
  goodPrompt="가입 폼과 결제 완료 화면의 문구를 더 친절하게 다듬되, 핵심 행동이 흐려지지 않게 해주세요. 버튼 텍스트, 오류 메시지, 도움말 문구를 각각 역할에 맞게 짧고 명확하게 정리해주세요."
/>

## 더 좋은 요청으로 바꾸는 방법

마이크로카피를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 화면과 어떤 요소의 문구인지
- 문구의 목적이 설명인지 행동 유도인지
- 사용자가 불안하거나 자주 실수하는 지점이 어디인지
- 브랜드 톤은 유지하되 얼마나 직설적이어야 하는지

<PromptCodeBlock>
회원가입 폼의 마이크로카피를 정리해주세요.
입력 필드 라벨, placeholder, 검증 오류 메시지, 제출 버튼 문구를 각각 역할에 맞게 써주고,
처음 쓰는 사용자도 바로 이해할 수 있게 짧고 명확한 한국어로 작성해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
삭제 확인 모달의 문구를 다시 써주세요.
사용자가 무엇을 삭제하는지 분명히 보이게 하고,
되돌릴 수 없는 작업이라는 점은 강조하되 과하게 위협적이지 않게 해주세요.
기본 버튼과 위험 버튼의 텍스트도 함께 제안해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
결제 실패 화면의 마이크로카피를 설계해주세요.
실패 이유를 짧게 설명하고, 사용자가 다음으로 할 수 있는 행동을 1~2개로 제시해주세요.
오류 코드 노출이 필요하면 사람도 이해할 수 있는 설명과 같이 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="친절함과 장황함은 다릅니다">
문구가 길어질수록 읽지 않을 가능성이 커집니다. 중요한 정보는 짧고 직접적으로 말해야 합니다.
</Callout>

## 구현 체크리스트

- 버튼 문구가 행동을 분명히 설명하는가
- 오류 메시지가 원인과 다음 행동을 함께 안내하는가
- 같은 톤과 용어가 전체 화면에서 일관적인가
- placeholder가 라벨 역할까지 대신하지 않는가
- 불필요한 군더더기 문장이 없는가

## 자주 헷갈리는 개념 비교

### 마이크로카피 vs 마케팅 카피

- 마이크로카피는 기능 사용을 돕는 문구입니다.
- 마케팅 카피는 설득과 전환을 위한 메시지입니다.

### 마이크로카피 vs CTA

- 마이크로카피는 더 넓은 범위의 짧은 UI 문구입니다.
- CTA는 그중에서도 행동 유도 요소에 더 집중합니다.

### 마이크로카피 vs 오류 상태

- 마이크로카피는 모든 UI에 들어가는 문구 개념입니다.
- 오류 상태는 실패 화면과 흐름 전반의 패턴입니다.
