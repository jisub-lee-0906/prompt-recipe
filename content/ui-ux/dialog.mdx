# 다이얼로그

> 한 줄 정의: 다이얼로그는 사용자에게 확인이나 간단한 입력을 요청하기 위해 구조화된 상호작용 창을 띄우는 패턴입니다.

## 왜 중요한가

실무에서 다이얼로그는 모달과 비슷해 보이지만, 특히 확인과 입력 목적이 더 분명한 구조로 자주 쓰입니다. "작은 창 열어줘" 같은 모호한 요청만으로는 제목, 설명, 버튼 역할, 닫힘 규칙이 빠진 불완전한 UI가 나오기 쉽습니다.

즉 다이얼로그는 단순 오버레이가 아니라, 사용자의 결정을 받는 작은 흐름입니다.

## 언제 쓰는가

- 삭제, 저장, 이동 전 확인을 받을 때
- 간단한 이름 입력이나 옵션 선택을 받을 때
- 현재 화면을 떠나지 않고 짧게 결정을 받아야 할 때

## 언제 쓰지 말아야 하는가

- 입력 필드가 너무 많아 별도 페이지가 더 적절할 때
- 단순 성공 안내처럼 확인이 필요 없는 경우
- 보조 설명만 보여주면 되는 경우

<Callout type="tip" title="다이얼로그는 짧고 분명한 결정에 적합합니다">
입력이 간단하고 현재 화면 안에서 바로 끝낼 수 있는 작업일수록 다이얼로그가 효과적입니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "이름 입력창 띄워줘"
- "확인 창 만들어줘"
- "버튼 누르면 작은 팝업 열리게 해줘"

이 요청에는 제목, 설명, 버튼 역할, 닫힘 규칙이 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 질문을 던지는 창인지 명확히 쓰기
- 확인 버튼과 취소 버튼 역할을 분리하기
- 입력 필드 수와 유효성 조건을 적기
- 닫힘 방식과 성공 후 동작을 함께 적기

## 복붙 가능한 프롬프트 예시

### 1. 새 폴더 입력 다이얼로그

<PromptCodeBlock>
새 폴더 만들기 버튼을 누르면 입력 다이얼로그가 열리게 해주세요.
제목은 "새 폴더 만들기"로 표시하고, 폴더 이름 입력창과 취소/생성 버튼을 넣어주세요.
입력값이 비어 있으면 생성 버튼을 비활성화하고, 생성 성공 후에는 다이얼로그를 닫아주세요.
</PromptCodeBlock>

### 2. 문서 제목 변경 다이얼로그

<PromptCodeBlock>
문서 제목 변경 다이얼로그를 만들어주세요.
현재 제목을 기본값으로 보여주고, 저장을 누르면 목록과 상세 화면 모두 즉시 갱신되게 해주세요.
ESC나 닫기 버튼으로 취소할 수 있게 해주세요.
</PromptCodeBlock>

### 3. 삭제 확인 다이얼로그

<PromptCodeBlock>
문서 삭제 버튼을 누르면 확인 다이얼로그가 열리게 해주세요.
본문에는 삭제 후 복구할 수 없다는 경고를 보여주고, 취소와 삭제 버튼을 분리해주세요.
삭제 버튼은 위험 액션처럼 보이게 강조해주시고, 성공 후에는 토스트도 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="입력 필드가 많아지면 다이얼로그보다 별도 페이지가 낫습니다">
짧은 결정과 간단한 입력은 다이얼로그에 잘 맞지만, 여러 단계 폼은 별도 페이지로 빼는 편이 사용성이 더 좋습니다.
</Callout>

## 구현 체크리스트

- 제목과 목적이 분명한가
- 취소와 확인 버튼 역할이 명확한가
- 입력 필드 수가 과하지 않은가
- ESC, 닫기 버튼, 바깥 클릭 규칙이 정해져 있는가
- 성공 후 어떤 변화가 생기는지 정의되어 있는가

## 자주 헷갈리는 개념 비교

### 다이얼로그 vs 모달

- 다이얼로그: 확인과 입력 목적이 더 분명한 구조
- 모달: 더 넓은 의미의 오버레이 패턴

### 다이얼로그 vs 팝오버

- 다이얼로그: 결정을 받는 데 더 적합
- 팝오버: 보조 선택지나 설정에 더 적합

### 다이얼로그 vs 토스트

- 다이얼로그: 사용자의 응답이 필요하다
- 토스트: 결과를 짧게 알리는 데 초점이 있다
