# 릴리스 체크리스트

> 한 줄 정의: 릴리스 체크리스트는 기능 배포 전에 반드시 확인해야 할 항목을 목록으로 정리한 운영용 점검 도구입니다.

## 왜 중요한가

기능이 구현되었다고 바로 배포 가능한 것은 아닙니다. 로그인, 권한, 에러 대응, 분석 이벤트, 모바일 대응처럼 마지막에 빠지기 쉬운 항목을 놓치면 실제 운영에서 바로 문제가 납니다. AI IDE에게 "배포 전에 점검해줘"라고만 말하면 포괄적인 조언만 나오기 쉬워서 점검 범위와 완료 기준을 분명히 해야 합니다.

## 언제 쓰는가

- 신규 기능을 배포하기 직전
- 디자인 변경이나 결제 흐름 같은 위험도가 높은 수정 전
- QA, PM, 개발자가 같은 완료 기준으로 마지막 점검을 할 때

## 언제 쓰지 말아야 하는가

- 기능마다 다른 위험도를 무시하고 체크리스트를 기계적으로 복붙할 때
- 체크 항목은 많은데 실제로 검증할 책임자가 없을 때
- 수용 기준과 연결되지 않아 왜 체크하는지 모를 때

<Callout type="tip" title="체크리스트는 완료 선언 도구가 아니라 누락 방지 도구입니다">
배포 전에 꼭 확인해야 할 것만 남겨야 실제로 읽히고 효과가 있습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="배포 전에 체크리스트 하나 만들어주세요."
  goodPrompt="회원가입 개편 기능을 배포하기 전에 확인해야 할 기능, 접근성, 모바일 대응, 분석 이벤트, 실패 시나리오, 롤백 항목을 체크리스트로 정리해주세요. 각 항목은 실제로 확인 가능한 문장으로 써주세요."
/>

## 더 좋은 요청으로 바꾸는 방법

릴리스 체크리스트를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 기능을 배포하는지
- 위험도가 높은 영역이 무엇인지
- 기능 검증 외에 운영, 분석, 롤백까지 포함할지
- 누가 어떤 항목을 확인할지

<PromptCodeBlock>
문서 발행 기능 배포용 릴리스 체크리스트를 만들어주세요.
기능 정상 동작, 권한 정책, 실패 시나리오, 분석 이벤트, 모바일 레이아웃, 롤백 준비 여부까지 포함해주세요.
체크 항목은 "확인한다"가 아니라 실제 검증 가능한 문장으로 써주세요.
</PromptCodeBlock>

<PromptCodeBlock>
결제 플로우 개편 배포 전 체크리스트를 정리해주세요.
성공 경로뿐 아니라 결제 실패, 중복 결제 방지, 환불 진입, 고객센터 연결 문구, 로그와 모니터링 준비까지 포함해주세요.
QA가 바로 사용할 수 있는 형식이면 좋겠습니다.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 대시보드 신규 검색 기능 배포 체크리스트를 작성해주세요.
브라우저별 확인, 큰 데이터셋에서 성능 저하 여부, 접근 권한, 검색 결과 없음 상태, 에러 상태, 검색 API 로그 확인 항목을 포함해주세요.
</PromptCodeBlock>

<Callout type="warning" title="체크리스트와 수용 기준은 연결되어야 합니다">
체크리스트는 수용 기준을 운영 단계에서 다시 검증하는 도구여야 합니다. 별개로 관리하면 중복되거나 빈 구멍이 생깁니다.
</Callout>

## 구현 체크리스트

- 기능 핵심 흐름 확인 항목이 있는가
- 실패 시나리오 확인 항목이 있는가
- 모바일과 접근성 확인 항목이 있는가
- 로그, 모니터링, 분석 이벤트 점검 항목이 있는가
- 롤백 또는 대응 계획 확인 항목이 있는가

## 자주 헷갈리는 개념 비교

### 릴리스 체크리스트 vs 수용 기준

- 수용 기준은 기능이 완성되었는지 판단하는 기준입니다.
- 릴리스 체크리스트는 배포 직전 실제로 빠진 것이 없는지 확인하는 목록입니다.

### 릴리스 체크리스트 vs 성공 기준

- 성공 기준은 제품 목표 관점의 판단 기준입니다.
- 릴리스 체크리스트는 배포 실행 관점의 안전 점검 목록입니다.

### 릴리스 체크리스트 vs 실패 시나리오

- 실패 시나리오는 문제가 생겼을 때 어떤 상황을 대비해야 하는지 정리합니다.
- 릴리스 체크리스트는 그 대비가 실제로 준비되었는지 확인합니다.
