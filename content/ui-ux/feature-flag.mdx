# 기능 플래그

> 한 줄 정의: 기능 플래그는 코드를 배포한 뒤에도 기능 노출 여부를 별도로 제어할 수 있게 하는 장치입니다.

## 왜 중요한가

새 기능을 모든 사용자에게 한 번에 열어버리면 문제가 생겼을 때 대응이 어렵습니다. 기능 플래그를 쓰면 내부 사용자만 먼저 보게 하거나 단계적으로 공개할 수 있습니다. AI IDE에게 "나중에 켜고 끌 수 있게 해줘"보다 기능 플래그라고 명시해야 노출 범위와 운영 흐름이 더 명확해집니다.

## 언제 쓰는가

- 새 기능을 내부 테스트 후 점진적으로 공개하고 싶을 때
- 위험도가 있는 기능을 빠르게 끄는 안전장치가 필요할 때
- A/B 테스트나 사용자 그룹별 노출 제어가 필요할 때

## 언제 쓰지 말아야 하는가

- 한 번 공개되면 다시 끌 일이 없는 아주 단순한 정적 문서에서
- 기능 플래그를 너무 많이 쌓아 코드 가독성을 크게 해칠 때

<Callout type="tip" title="기능 플래그는 출시보다 회수 전략에도 강합니다">
문제가 생겼을 때 배포를 되돌리지 않고도 기능만 끌 수 있다는 점이 큰 장점입니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

기능 플래그를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 기능을 감쌀지
- 누구에게 먼저 노출할지
- 꺼져 있을 때의 기본 동작이 무엇인지
- 문제가 생기면 어떻게 회수할지

<PromptCodeBlock>
새 검색 모달 기능을 기능 플래그로 감싸주세요.
내부 사용자에게만 먼저 노출하고, 문제가 없으면 전체 사용자에게 단계적으로 열 수 있게 해주세요.
플래그가 꺼져 있을 때는 기존 검색 버튼이 그대로 동작해야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
새 대시보드 카드 레이아웃을 기능 플래그 뒤에 두고 운영할 수 있게 해주세요.
디자인 검증 전에는 내부 계정만 보게 하고, 필요하면 기존 레이아웃으로 바로 되돌릴 수 있게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
새 결제 흐름을 기능 플래그로 제어해주세요.
베타 사용자 그룹만 먼저 사용하게 하고, 장애가 발생하면 즉시 기존 결제 흐름으로 폴백되게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="기능 플래그는 임시 장치인데 오래 남기면 기술 부채가 됩니다">
언제 제거할지 계획 없이 계속 쌓이면 코드 경로가 급격히 복잡해집니다. 종료 시점도 함께 정하는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 어떤 기능이 플래그 대상인지 분명한가
- 노출 대상과 기본값이 정의되어 있는가
- 플래그가 꺼졌을 때 기본 동작이 자연스러운가
- 문제 발생 시 회수 경로가 있는가
- 플래그 제거 시점도 고려했는가

## 자주 헷갈리는 개념 비교

### 기능 플래그 vs 배포

- 기능 플래그는 노출 제어입니다.
- 배포는 코드 반영 자체입니다.

### 기능 플래그 vs 롤백

- 기능 플래그는 기능만 끄는 빠른 장치입니다.
- 롤백은 코드나 배포 상태를 이전으로 되돌리는 전략입니다.

### 기능 플래그 vs 폴백

- 기능 플래그는 노출 여부를 제어합니다.
- 폴백은 실패했을 때 다른 경로로 대체합니다.
