# 시트

> 한 줄 정의: 시트는 화면 한쪽에서 밀려 나와 보조 작업이나 탐색을 지원하는 패널형 UI입니다.

## 왜 중요한가

모바일 내비게이션, 필터, 설정처럼 본문을 완전히 떠나지 않고 추가 기능을 보여주고 싶을 때 시트가 유용합니다. AI IDE에게 "옆에서 나오게 해줘"보다 시트라고 명시하면 열리는 방향, 배경 차단 정도, 닫기 방식까지 더 구체적으로 설계할 수 있습니다.

## 언제 쓰는가

- 모바일 메뉴나 사이드바 대체 UI가 필요할 때
- 필터, 설정, 상세 옵션을 본문 옆에서 열고 싶을 때
- 화면 전환 없이 보조 작업을 처리하고 싶을 때

## 언제 쓰지 말아야 하는가

- 강한 경고나 필수 확인처럼 모달 수준의 집중이 필요한 상황일 때
- 간단한 tooltip이나 popover로 충분한 짧은 정보일 때
- 화면 전체를 거의 덮어 사실상 별도 페이지처럼 쓰려 할 때

<Callout type="tip" title="시트는 본문과의 연결감을 유지하는 데 강합니다">
사용자가 현재 화면 문맥을 잃지 않은 채 보조 작업을 할 수 있어야 시트의 장점이 살아납니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

시트를 요청할 때는 아래를 같이 말해야 합니다.

- 어느 방향에서 열릴지
- 배경을 차단할지
- 닫는 방법이 무엇인지
- 이동이나 저장 후 자동으로 닫아야 하는지

<PromptCodeBlock>
모바일에서는 왼쪽에서 열리는 시트로 내비게이션을 보여주세요.
배경은 어둡게 처리하고, 바깥 영역을 누르거나 닫기 버튼을 누르면 닫히게 해주세요.
메뉴 항목을 누르면 이동 후 시트도 자동으로 닫혀야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
데스크톱에서는 상단 필터 바를 유지하고, 모바일에서는 필터 조건을 오른쪽 시트 안에 넣어주세요.
적용 버튼과 초기화 버튼을 시트 하단에 고정해 작은 화면에서도 쉽게 누를 수 있게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 상세 화면에서 관련 문서 목록을 보조 시트로 열 수 있게 해주세요.
본문을 떠나지 않고 다른 문서를 탐색할 수 있어야 하고, 시트 안에서도 검색과 카테고리 필터가 가능하게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="시트를 페이지 대체물처럼 쓰면 복잡도가 급격히 올라갑니다">
시트는 보조 영역입니다. 주요 플로우 전체를 시트 안에 욱여넣으면 닫기, 뒤로 가기, 스크롤 처리까지 금방 복잡해집니다.
</Callout>

## 구현 체크리스트

- 열리는 방향과 크기가 목적에 맞는가
- 닫기 경로가 명확한가
- 이동 후 자동 닫힘 같은 후속 동작이 정의되어 있는가
- 모바일에서 조작이 쉬운가
- 본문 문맥을 잃지 않게 설계되어 있는가

## 자주 헷갈리는 개념 비교

### 시트 vs 드로어

- 실무에서는 거의 비슷하게 쓰이지만, 시트는 보조 패널 의미가 더 강하고 드로어는 내비게이션 맥락에서 더 자주 쓰입니다.

### 시트 vs 모달

- 시트는 본문과 연결된 보조 패널입니다.
- 모달은 현재 작업을 잠시 멈추고 집중시켜야 하는 상자입니다.

### 시트 vs 팝오버

- 시트는 더 큰 공간과 강한 존재감을 가집니다.
- 팝오버는 작고 문맥 가까운 패널입니다.
