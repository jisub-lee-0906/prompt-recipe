# 확인 흐름

> 한 줄 정의: 확인 흐름은 중요하거나 되돌리기 어려운 행동 직전에 사용자의 의도를 다시 묻는 UX 설계입니다.

## 왜 중요한가

삭제, 탈퇴, 결제 확정처럼 되돌리기 어려운 행동은 한 번의 실수로도 큰 피해를 만들 수 있습니다. AI IDE에게 "정말 할 건지 물어봐줘"라고 하는 것보다 확인 흐름이라고 정확히 요청해야 어떤 단계에서 확인할지, 얼마나 강하게 경고할지, 취소 경로는 무엇인지까지 제대로 설계할 수 있습니다.

## 언제 쓰는가

- 삭제, 탈퇴, 결제 확정처럼 복구가 어렵거나 위험한 행동 앞에서
- 대량 변경, 권한 변경처럼 영향 범위가 큰 액션 앞에서
- 사용자의 실수가 자주 발생할 수 있는 중요한 전환 지점에서

## 언제 쓰지 말아야 하는가

- 사소하고 자주 반복되는 일반 행동마다 붙일 때
- 확인이 너무 자주 나와 실제로 중요한 경고까지 무뎌질 때
- 되돌리기 쉬운 액션인데도 과도하게 막아 흐름만 끊을 때

<Callout type="warning" title="확인은 많을수록 좋은 것이 아닙니다">
모든 액션에 확인 단계를 넣으면 사용자는 점점 경고를 읽지 않게 됩니다. 정말 위험하거나 복구 불가능한 행동에만 써야 효과가 있습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="삭제 전에 한 번 더 물어봐주세요."
  goodPrompt="사용자 계정 삭제 전에 확인 흐름을 추가해주세요. 첫 단계에서는 일반 확인 모달을 보여주고, 두 번째 단계에서는 삭제 후 복구가 불가능하다는 점을 더 강하게 강조해주세요. 취소 버튼과 위험 버튼의 우선순위가 분명해야 합니다."

## 더 좋은 요청으로 바꾸는 방법

확인 흐름을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 행동이 위험한지
- 한 단계 확인인지 두 단계 확인인지
- 복구 가능 여부를 어떻게 설명할지
- 취소, 뒤로 가기, 실패 시 경로가 무엇인지

<PromptCodeBlock>
사용자 계정 삭제 전에 확인 흐름을 추가해주세요.
첫 단계에서는 일반 확인 모달을 보여주고, 두 번째 단계에서는 삭제 후 복구가 불가능하다는 점을 더 강하게 강조해주세요.
취소 버튼과 위험 버튼의 우선순위가 분명해야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
게시글 영구 삭제 전에 확인 다이얼로그를 보여주세요.
삭제 후 복구할 수 없다는 설명과 함께 `취소`, `삭제` 버튼을 분리해주고, 삭제 버튼은 위험 색상으로 처리해주세요.
실패하면 에러 메시지를 보여주고 다이얼로그는 닫지 말아주세요.
</PromptCodeBlock>

<PromptCodeBlock>
결제 확정 직전에 확인 흐름을 넣어주세요.
주문 상품, 총 결제 금액, 결제 수단을 마지막으로 다시 보여주고 `결제하기`를 누르면 버튼만 로딩 상태가 되게 해주세요.
취소하면 이전 단계로 돌아가고, 이미 결제가 진행 중일 때는 중복 요청을 막아주세요.
</PromptCodeBlock>

<Callout type="tip" title="중요도가 높을수록 메시지와 버튼 위계가 더 분명해야 합니다">
위험 버튼은 시각적으로 분명해야 하고, 취소 경로도 쉽게 보여야 합니다. 그래야 사용자가 실수로 잘못된 버튼을 누르지 않습니다.
</Callout>

## 구현 체크리스트

- 정말 중요한 액션에만 확인이 붙는가
- 복구 가능 여부가 분명히 설명되는가
- 취소와 확인 버튼의 우선순위가 명확한가
- 실패 시 사용자 복구 경로가 있는가
- 중복 실행을 막는가

## 자주 헷갈리는 개념 비교

### 확인 흐름 vs 모달

- 확인 흐름은 사용자 의도를 재확인하는 UX 개념입니다.
- 모달은 그 흐름을 구현하는 한 가지 UI 방식입니다.

### 확인 흐름 vs 다이얼로그

- 확인 흐름은 전체 단계 설계입니다.
- 다이얼로그는 그 단계에서 사용하는 상자 형태 UI입니다.

### 확인 흐름 vs 토스트

- 확인 흐름은 행동 전에 보여줍니다.
- 토스트는 행동 후 결과를 짧게 알려줍니다.
