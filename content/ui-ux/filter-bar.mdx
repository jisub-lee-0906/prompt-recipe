# 필터 바

> 한 줄 정의: 필터 바는 사용자가 조건을 선택해 목록 범위를 빠르게 좁힐 수 있게 만드는 컨트롤 묶음입니다.

## 왜 중요한가

문서나 상품이 많아질수록 사용자는 전체를 훑기보다 조건을 걸어 범위를 줄이길 원합니다. AI IDE에게 "필터 좀 넣어줘"라고만 하면 버튼 몇 개가 붙는 수준에 그치기 쉽습니다. 필터 바라고 정확히 요청해야 현재 선택 상태, 초기화, 결과 반영 방식까지 함께 설계할 수 있습니다.

## 언제 쓰는가

- 카테고리, 태그, 가격, 상태처럼 여러 조건으로 목록을 좁혀야 할 때
- 검색 결과와 함께 추가 조건을 걸어야 할 때
- 관리자 테이블이나 문서 목록처럼 항목 수가 많을 때

## 언제 쓰지 말아야 하는가

- 결과 수가 적어서 필터 없이도 바로 훑어볼 수 있을 때
- 조건이 너무 많아 오히려 화면만 복잡해질 때
- 단일 정렬 옵션 정도만 필요한데 필터 바 전체를 만들려 할 때

<Callout type="tip" title="필터 바는 현재 선택 상태가 항상 보여야 합니다">
무엇이 적용됐는지 바로 보이지 않으면 사용자는 결과가 왜 바뀌었는지 이해하기 어렵습니다. 선택된 조건과 해제 경로가 함께 보여야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

## 더 좋은 요청으로 바꾸는 방법

필터 바를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 조건으로 필터링할지
- 현재 선택 상태를 어떻게 보여줄지
- 초기화 버튼이 필요한지
- 모바일에서 접거나 시트로 분리할지

<PromptCodeBlock>
문서 목록 상단에 필터 바를 추가해주세요.
카테고리, 태그, 난이도 기준으로 결과를 좁힐 수 있게 하고, 현재 선택된 필터는 칩 형태로 보여주세요.
`전체 초기화` 버튼도 함께 넣어주세요.
</PromptCodeBlock>

<PromptCodeBlock>
상품 목록 상단에 필터 바를 만들어주세요.
브랜드, 가격대, 재고 여부를 필터링할 수 있게 하고, 적용된 필터 개수를 한눈에 볼 수 있게 해주세요.
모바일에서는 필터 바 전체를 시트 안으로 넣고, 데스크톱에서는 가로 바 형태로 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 결과 화면에 필터 바를 추가해주세요.
검색어는 유지한 채 카테고리와 태그 필터를 함께 걸 수 있게 하고, 현재 적용 중인 필터를 제거할 수 있는 칩도 보여주세요.
필터 변경 시 결과 개수도 함께 갱신해주세요.
</PromptCodeBlock>

<Callout type="warning" title="조건이 많아질수록 노출 방식도 함께 설계해야 합니다">
모든 필터를 한 줄에 다 올리면 화면이 금방 무거워집니다. 자주 쓰는 조건만 먼저 보이고, 나머지는 시트나 드롭다운으로 넘기는 방식이 더 낫습니다.
</Callout>

## 구현 체크리스트

- 현재 적용된 필터가 명확히 보이는가
- 필터 해제와 전체 초기화 경로가 있는가
- 결과 개수나 목록 변화가 자연스럽게 반영되는가
- 모바일과 데스크톱 구조가 구분되어 있는가
- 검색 바와 함께 써도 역할이 겹치지 않는가

## 자주 헷갈리는 개념 비교

### 필터 바 vs 검색 바

- 필터 바는 범위를 좁힙니다.
- 검색 바는 원하는 대상을 직접 찾습니다.

### 필터 바 vs 정렬

- 필터 바는 결과 집합 자체를 줄입니다.
- 정렬은 같은 결과 집합의 순서를 바꿉니다.

### 필터 바 vs 드롭다운

- 필터 바는 여러 조건을 묶은 상위 영역입니다.
- 드롭다운은 그 안에서 쓸 수 있는 개별 입력 방식 중 하나입니다.
