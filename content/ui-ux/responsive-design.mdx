# 반응형 설계

> 한 줄 정의: 반응형 설계는 화면 크기가 달라져도 콘텐츠와 기능이 자연스럽게 사용되도록 구조를 조정하는 방식입니다.

## 왜 중요한가

데스크톱 화면만 기준으로 설계하면 모바일에서 금방 깨집니다. 반대로 단순히 폭만 줄이는 것으로는 충분하지 않습니다. 어떤 요소를 숨기고, 어떤 요소를 접고, 어떤 흐름을 우선할지까지 같이 설계해야 합니다. AI IDE에게 "모바일도 되게 해줘"보다 반응형 설계라고 명시하는 편이 훨씬 정확합니다.

## 언제 쓰는가

- 데스크톱과 모바일 모두에서 써야 하는 서비스 전반
- 사이드바, TOC, 카드 그리드처럼 화면 폭에 따라 구조가 크게 바뀌는 UI
- 입력 폼이나 대시보드처럼 작은 화면에서 우선순위 조정이 필요한 경우

## 언제 쓰지 말아야 하는가

- 예외가 거의 없습니다. 웹 화면이라면 기본적으로 반응형 설계가 필요합니다.

<Callout type="tip" title="반응형은 폭 축소가 아니라 우선순위 재배치입니다">
작아진 화면에서는 덜 중요한 요소를 접거나 숨기고, 본문과 주요 행동을 먼저 보여줘야 합니다. 같은 레이아웃을 억지로 줄이는 것은 좋은 반응형이 아닙니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

반응형 설계를 요청할 때는 아래를 같이 말해야 합니다.

- 화면 크기별로 어떤 구조가 바뀌는지
- 숨겨질 요소와 유지될 요소가 무엇인지
- 모바일에서 대체 UI가 필요한지
- 카드 열 수나 리스트 구조가 어떻게 달라지는지

<PromptCodeBlock>
문서 페이지를 반응형으로 설계해주세요.
데스크톱에서는 좌측 사이드바와 우측 TOC를 함께 보여주고, 모바일에서는 본문 중심 구조로 바꾸며 사이드바와 TOC는 드로어나 시트로 옮겨주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 카드 목록을 반응형으로 설계해주세요.
데스크톱은 3열, 태블릿은 2열, 모바일은 1열로 바꾸고, 카드 간격도 화면 폭에 맞게 줄어들게 해주세요.
모바일에서는 태그 수가 너무 많으면 일부만 보이고 나머지는 숨겨주세요.
</PromptCodeBlock>

<PromptCodeBlock>
설정 화면을 반응형으로 바꿔주세요.
데스크톱에서는 왼쪽 고정 메뉴와 오른쪽 본문 구조를 유지하고, 모바일에서는 메뉴를 상단 탭이나 시트로 바꿔주세요.
저장 버튼은 작은 화면에서도 항상 누르기 쉬운 위치에 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="데스크톱 구조를 그대로 줄이면 모바일 UX가 나빠집니다">
넓은 화면에서 유효한 3단 구조가 작은 화면에서도 그대로 유지될 필요는 없습니다. 모바일에서는 집중 흐름을 더 강하게 만들어야 합니다.
</Callout>

## 구현 체크리스트

- 화면 크기별 구조 변화가 정의되어 있는가
- 숨길 요소와 대체 UI가 명확한가
- 주요 행동이 모바일에서도 쉽게 보이는가
- 텍스트와 버튼이 터치 가능한 크기를 유지하는가
- 레이아웃 붕괴 없이 자연스럽게 바뀌는가

## 자주 헷갈리는 개념 비교

### 반응형 설계 vs 반응형 레이아웃

- 반응형 설계는 더 넓은 전략 개념입니다.
- 반응형 레이아웃은 그 전략을 실제 레이아웃 구조로 구현한 결과입니다.

### 반응형 설계 vs 접근성

- 반응형 설계는 화면 크기 변화 대응에 집중합니다.
- 접근성은 입력 방식과 사용 가능성 전반을 다룹니다.

### 반응형 설계 vs 모바일 우선

- 반응형 설계는 여러 화면 크기를 함께 다룹니다.
- 모바일 우선은 작은 화면을 기준으로 시작하는 접근입니다.
