# 스켈레톤

> 한 줄 정의: 스켈레톤은 로딩 중인 화면에서 최종 콘텐츠의 구조를 미리 보여줘 사용자가 기다릴 이유를 이해하게 만드는 패턴입니다.

## 왜 중요한가

단순 스피너만 보여주면 사용자는 무엇이 얼마나 걸리는지 알기 어렵습니다. 반대로 스켈레톤은 제목, 카드, 본문, 사이드 영역 같은 실제 구조를 먼저 보여주기 때문에 기다림이 덜 불안하게 느껴집니다. AI IDE에게 "로딩 UI" 대신 "스켈레톤"이라고 정확히 요청해야 결과가 훨씬 좋아집니다.

## 언제 쓰는가

- 카드 목록, 피드, 문서 목록처럼 반복 구조가 명확할 때
- 상세 페이지에서 제목과 본문 구조를 미리 보여주고 싶을 때
- 로딩 시간이 아주 길지는 않지만 빈 화면으로 두기엔 어색할 때

## 언제 쓰지 말아야 하는가

- 응답이 거의 즉시 끝나는 가벼운 인터랙션일 때
- 실제 구조를 알 수 없거나 최종 레이아웃이 자주 바뀌는 화면일 때
- 긴 로딩인데도 설명 없이 스켈레톤만 계속 보여줘 오히려 멈춘 것처럼 느껴질 때

<Callout type="tip" title="좋은 스켈레톤은 최종 레이아웃을 닮아야 합니다">
회색 막대 몇 개만 임의로 넣는 것보다 제목, 이미지, 태그, 버튼 위치를 실제와 비슷하게 맞추는 편이 훨씬 자연스럽습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

스켈레톤을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 화면 구조를 따라갈지
- 몇 개를 먼저 보여줄지
- 화면 전체인지 일부 영역인지
- 로딩이 길어질 때 보조 안내가 필요한지

<PromptCodeBlock>
문서 카드 목록을 불러오는 동안 실제 카드 구조를 닮은 스켈레톤 카드 6개를 보여주세요.
제목, 설명, 태그 위치가 최종 카드와 비슷해야 하고, 데이터가 도착하면 레이아웃 점프가 크지 않게 자연스럽게 바뀌어야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
문서 상세 페이지 로딩 중에는 제목, 설명, 본문, 우측 TOC 자리를 각각 스켈레톤으로 보여주세요.
단순 스피너 대신 실제 화면 구조를 먼저 보여줘서 사용자가 문서가 곧 나타날 것이라고 예측할 수 있게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 조건을 바꿨을 때 결과 목록 영역만 부분 스켈레톤으로 처리해주세요.
헤더와 필터 바는 유지하고, 카드 목록 자리만 다시 그려지도록 해서 페이지 전체가 깜빡이지 않게 해주세요.
로딩이 2초 이상 길어지면 `결과를 다시 불러오는 중입니다` 같은 안내 문구도 함께 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="스켈레톤이 너무 오래 보이면 에러처럼 느껴질 수 있습니다">
짧은 로딩에는 효과적이지만, 긴 로딩에는 별도 안내 문구나 재시도 흐름이 함께 있어야 합니다. 그렇지 않으면 사용자는 화면이 멈췄다고 생각할 수 있습니다.
</Callout>

## 구현 체크리스트

- 최종 레이아웃과 시각적으로 충분히 닮았는가
- 화면 전체를 막지 않고 필요한 영역만 로딩 처리하는가
- 데이터 도착 후 레이아웃 점프가 과하지 않은가
- 긴 로딩 시 추가 안내가 있는가
- 빈 상태나 에러 상태와 혼동되지 않는가

## 자주 헷갈리는 개념 비교

### 스켈레톤 vs 로딩 상태

- 스켈레톤은 로딩 상태를 표현하는 한 가지 방식입니다.
- 로딩 상태는 더 넓은 개념이고 스피너, 진행 바, 버튼 로딩도 포함합니다.

### 스켈레톤 vs 빈 상태

- 스켈레톤은 결과를 아직 가져오는 중입니다.
- 빈 상태는 결과가 0개로 확정된 상태입니다.

### 스켈레톤 vs 스피너

- 스켈레톤은 최종 구조를 미리 보여줍니다.
- 스피너는 처리 중이라는 사실만 간단히 보여줍니다.
