# 온보딩

> 한 줄 정의: 온보딩은 처음 들어온 사용자가 서비스 목적과 기본 사용법을 빠르게 이해하도록 돕는 초기 경험 설계입니다.

## 왜 중요한가

좋은 기능이 있어도 첫 사용자가 어떻게 시작해야 할지 모르면 이탈이 쉽게 발생합니다. AI IDE에게 "첫 화면 좀 친절하게 만들어줘"보다 "온보딩 흐름을 설계해줘"라고 말해야 시작 단계, 안내 방식, 생략 가능 여부까지 더 잘 잡힙니다.

## 언제 쓰는가

- 처음 방문한 사용자가 무엇을 해야 할지 바로 알기 어려울 때
- 복잡한 기능이나 개념을 짧게 설명해줘야 할 때
- 가입 직후 첫 행동을 유도해야 할 때

## 언제 쓰지 말아야 하는가

- 제품이 너무 단순해서 별도 설명 없이도 바로 사용할 수 있을 때
- 모든 사용자에게 긴 안내를 강제로 보여 오히려 진입을 막을 때
- 나중에 다시 볼 수 없는 방식으로만 중요한 정보를 전달할 때

<Callout type="tip" title="좋은 온보딩은 설명보다 첫 행동 유도에 가깝습니다">
길게 읽게 만드는 것보다 사용자가 바로 첫 작업을 시작할 수 있게 돕는 편이 훨씬 효과적입니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

  goodPrompt="처음 방문한 사용자를 위한 온보딩 흐름을 설계해주세요. 서비스 목적을 짧게 소개하고, 핵심 기능 2~3개를 빠르게 이해할 수 있게 한 뒤, 마지막에는 `첫 문서 읽기` 같은 명확한 시작 CTA로 연결해주세요."
/>

## 더 좋은 요청으로 바꾸는 방법

온보딩을 요청할 때는 아래를 같이 말해야 합니다.

- 누구를 위한 첫 경험인지
- 설명보다 어떤 행동을 유도할지
- 몇 단계까지 보여줄지
- 건너뛰기나 나중에 다시 보기 기능이 필요한지

<PromptCodeBlock>
처음 방문한 사용자를 위한 온보딩 흐름을 설계해주세요.
서비스 목적을 짧게 소개하고, 핵심 기능 2~3개를 빠르게 이해할 수 있게 한 뒤, 마지막에는 `첫 문서 읽기` 같은 명확한 시작 CTA로 연결해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
가입 직후 보여줄 온보딩 화면을 만들어주세요.
사용자가 어떤 순서로 문서를 읽고 검색을 활용하면 좋은지 짧게 안내하고, `추천 문서 보기`와 `검색부터 시작하기` 두 경로를 제안해주세요.
건너뛰기 버튼도 함께 넣어주세요.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 도구 첫 진입 온보딩을 설계해주세요.
왼쪽 메뉴, 상단 필터, 주요 테이블 사용법을 한 번에 길게 설명하지 말고, 가장 중요한 3가지 기능만 짧게 보여준 뒤 실제 화면으로 진입하게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="온보딩을 튜토리얼처럼 길게 만들면 오히려 이탈을 부를 수 있습니다">
처음부터 모든 기능을 설명하려 하지 말고, 바로 시작할 수 있을 정도의 최소 안내만 제공하는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 첫 사용자가 무엇을 해야 하는지 바로 이해할 수 있는가
- 설명이 짧고 핵심 중심인가
- 건너뛰기나 나중에 다시 보기 경로가 필요한가
- 마지막에 명확한 CTA가 있는가
- 실제 제품 흐름과 연결되는가

## 자주 헷갈리는 개념 비교

### 온보딩 vs 빈 상태

- 온보딩은 첫 경험 전체를 다룹니다.
- 빈 상태는 데이터가 없을 때의 특정 화면을 다룹니다.

### 온보딩 vs 사용자 흐름

- 온보딩은 초기 적응에 초점을 둡니다.
- 사용자 흐름은 더 넓은 목표 달성 경로를 다룹니다.

### 온보딩 vs 히어로 섹션

- 온보딩은 사용 시작 이후 흐름까지 포함할 수 있습니다.
- 히어로 섹션은 첫 화면 메시지 전달에 집중합니다.
