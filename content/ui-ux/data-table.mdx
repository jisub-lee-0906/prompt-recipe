# 데이터 테이블

> 한 줄 정의: 데이터 테이블은 많은 항목을 행과 열 구조로 정리해 비교와 관리가 가능하게 만드는 UI 패턴입니다.

## 왜 중요한가

카드 레이아웃이 훑어보기에 강하다면, 데이터 테이블은 비교와 관리에 강합니다. 관리자 화면이나 운영 도구에서는 같은 속성을 여러 행에서 빠르게 비교해야 하는 경우가 많습니다. AI IDE에게 "표로 보여줘"보다 "데이터 테이블을 설계해줘"라고 말해야 정렬, 필터, 선택, 액션 컬럼까지 함께 고려됩니다.

## 언제 쓰는가

- 관리자 화면에서 사용자, 주문, 문서 목록을 관리할 때
- 여러 속성을 열 기준으로 비교해야 할 때
- 행 단위 액션이나 선택 기능이 필요할 때

## 언제 쓰지 말아야 하는가

- 데이터보다 시각적 탐색이 중요한 카드형 갤러리일 때
- 모바일에서 열 수가 너무 많아 테이블이 사실상 읽히지 않을 때
- 항목 수가 적고 비교 필요성이 낮을 때

<Callout type="tip" title="테이블은 비교 목적이 분명할 때 가장 강합니다">
행과 열이 있다는 이유만으로 테이블을 쓰기보다, 어떤 열을 서로 비교해야 하는지 먼저 분명해야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

<PromptCard
  badPrompt="관리자 목록 표로 보여주세요."

/>

## 더 좋은 요청으로 바꾸는 방법

데이터 테이블을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 열이 필요한지
- 정렬이나 필터가 필요한지
- 행 클릭과 행별 액션 중 무엇이 필요한지
- 모바일에서 어떻게 단순화할지

<PromptCodeBlock>
관리자 사용자 목록을 데이터 테이블로 구성해주세요.
이름, 이메일, 역할, 가입일, 상태를 열로 보여주고, 정렬 가능한 열과 행별 더보기 액션을 넣어주세요.
행 수가 많으면 페이지네이션도 함께 붙여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 관리 화면에 데이터 테이블을 만들어주세요.
문서 제목, 카테고리, 태그 수, 최근 수정일, 공개 여부를 열로 보여주고, 각 행 오른쪽에는 `수정`, `삭제` 액션 메뉴를 넣어주세요.
필터 바와 검색 바도 함께 붙여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
모바일에서는 데이터 테이블을 그대로 줄이지 말고, 핵심 열만 남기고 나머지는 상세 펼침이나 별도 화면으로 넘겨주세요.
터치하기 쉬운 행 높이와 더보기 버튼 크기도 고려해주세요.
</PromptCodeBlock>

<Callout type="warning" title="열이 너무 많으면 테이블이 아니라 스크롤 지옥이 됩니다">
보여주고 싶은 정보가 많아도 핵심 열만 먼저 보여주고, 나머지는 상세나 더보기로 넘기는 편이 낫습니다.
</Callout>

## 구현 체크리스트

- 비교해야 할 핵심 열이 분명한가
- 정렬과 필터가 필요한 열이 구분되는가
- 행 선택, 행 클릭, 행별 액션이 충돌하지 않는가
- 모바일 단순화 전략이 있는가
- 데이터 수가 많을 때 페이지네이션이나 가상화가 필요한가

## 자주 헷갈리는 개념 비교

### 데이터 테이블 vs 카드 레이아웃

- 데이터 테이블은 열 기준 비교에 강합니다.
- 카드 레이아웃은 객체 단위 훑어보기에 강합니다.

### 데이터 테이블 vs 리스트 렌더링

- 데이터 테이블은 리스트 렌더링의 한 표현 방식입니다.
- 리스트 렌더링은 더 넓은 반복 출력 개념입니다.

### 데이터 테이블 vs 페이지네이션

- 데이터 테이블은 데이터 표현 방식입니다.
- 페이지네이션은 많은 결과를 나눠 탐색하는 방식입니다.
