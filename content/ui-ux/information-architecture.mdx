# 정보 구조

> 한 줄 정의: 정보 구조는 콘텐츠와 화면을 어떤 분류 체계로 묶고 연결할지 정하는 설계입니다.

## 왜 중요한가

정보 구조가 흔들리면 URL, 사이드바, 검색, 브레드크럼, 카테고리가 모두 제각각 움직입니다. AI IDE에게 "메뉴 좀 정리해줘"라고만 하면 표면만 다듬게 되지만, 정보 구조를 먼저 설명하면 서비스 전체의 뼈대를 함께 설계할 수 있습니다.

## 언제 쓰는가

- 문서 사이트, 관리자 화면, 설정 화면처럼 카테고리와 메뉴가 많을 때
- 검색, 사이드바, URL 구조가 서로 연결되어야 할 때
- 기능이 늘어나기 전에 상위 분류 체계를 먼저 정해야 할 때

## 언제 쓰지 말아야 하는가

- 단일 랜딩 페이지 하나만 빠르게 만들 때
- 화면 수가 매우 적고 분류 체계가 사실상 필요 없을 때

<Callout type="info" title="정보 구조는 서비스 전체를 묶는 기준입니다">
상위 카테고리, URL, 검색 분류, 내비게이션 구조가 같은 기준을 따라야 사용자가 길을 잃지 않습니다. 정보 구조를 늦게 정하면 나중에 메뉴와 경로를 전부 다시 손봐야 할 수 있습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

정보 구조를 요청할 때는 아래를 같이 말해야 합니다.

- 최상위 카테고리가 무엇인지
- 사용자가 가장 자주 찾는 항목이 무엇인지
- URL과 메뉴가 같은 체계를 따라야 하는지
- 검색과 필터에도 같은 분류를 적용할지

<PromptCodeBlock>
문서 사이트의 정보 구조를 설계해주세요.
최상위 카테고리는 `UI/UX`, `프론트엔드`, `백엔드`, `기획/협업/품질`로 나누고, 사이드바, 검색 결과, URL 구조가 같은 분류 체계를 따르도록 정리해주세요.
각 문서는 카테고리와 slug 기준으로 상세 페이지를 갖게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
설정 화면의 정보 구조를 재정리해주세요.
`프로필`, `보안`, `알림`, `팀 관리`, `결제`를 최상위 섹션으로 두고, 왼쪽 메뉴와 URL 경로, 브레드크럼이 모두 같은 구조를 따라가게 해주세요.
사용자가 현재 어디 있는지 항상 알 수 있도록 메뉴 강조와 현재 위치 표시도 고려해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 화면의 정보 구조를 정리해주세요.
사용자 관리, 콘텐츠 관리, 통계, 권한 관리처럼 상위 영역을 먼저 나누고, 목록과 상세 화면의 경로 규칙까지 함께 정의해주세요.
검색 결과도 같은 카테고리 체계를 기준으로 묶일 수 있게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="정보 구조는 너무 자주 바꾸면 전체 UX가 흔들립니다">
초기에는 다소 거칠어도 분류 기준을 먼저 고정하는 편이 낫습니다. 중간에 기준이 자주 바뀌면 URL, 메뉴, 검색 인덱스, 문서 링크가 함께 흔들립니다.
</Callout>

## 구현 체크리스트

- 최상위 카테고리 기준이 명확한가
- URL, 메뉴, 검색 분류가 같은 체계를 따르는가
- 사용자가 현재 위치를 쉽게 파악할 수 있는가
- 비슷한 개념이 서로 다른 카테고리에 중복 배치되지 않는가
- 확장 시 새 문서를 자연스럽게 넣을 수 있는가

## 자주 헷갈리는 개념 비교

### 정보 구조 vs 사용자 흐름

- 정보 구조는 콘텐츠와 화면의 분류 체계입니다.
- 사용자 흐름은 사용자가 목표를 달성하는 이동 경로입니다.

### 정보 구조 vs 브레드크럼

- 정보 구조는 서비스 전체의 기준입니다.
- 브레드크럼은 그 구조 안에서 현재 위치를 보여주는 UI입니다.

### 정보 구조 vs 라우팅

- 정보 구조는 개념적 분류 체계입니다.
- 라우팅은 그 체계를 실제 URL과 페이지 구조로 구현하는 방식입니다.
