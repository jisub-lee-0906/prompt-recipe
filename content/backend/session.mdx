# 세션

> 한 줄 정의: 세션은 로그인한 사용자의 인증 상태를 서버 쪽에서 유지하고 식별하는 방식입니다.

## 왜 중요한가

사용자가 "로그인 상태 유지되게 해줘"라고 요청할 때, 구현 관점에서는 세션인지 토큰인지 방식이 달라집니다. 이 차이를 모르고 요청하면 로그인 화면만 생기고, 실제 인증 유지 방식은 비어 있게 될 수 있습니다.

세션은 로그인 이후 사용자가 계속 인증된 상태로 서비스를 쓸 수 있게 만드는 핵심 개념입니다.

## 언제 쓰는가

- 서버 중심 인증 구조를 쓸 때
- 민감한 권한 처리를 더 안전하게 다루고 싶을 때
- 쿠키 기반 로그인 유지가 필요한 웹 서비스일 때

## 언제 쓰지 말아야 하는가

- 여러 클라이언트 앱이 같은 인증 문자열을 직접 들고 다녀야 하는 구조일 때
- 로그인 유지가 필요 없는 공개 페이지일 때

<Callout type="tip" title="세션은 로그인 화면이 아니라 로그인 이후 상태를 설명하는 개념입니다">
사용자가 로그인한 뒤 페이지를 이동하거나 새로고침해도 인증 상태가 유지되는 흐름을 함께 생각해야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "로그인 유지되게 해줘"
- "새로고침해도 안 풀리게 해줘"
- "로그아웃 전까지 계속 로그인 상태로 남겨줘"

이 요청에는 세션 만료 시점, 로그아웃 처리, 만료 후 사용자 경험이 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 로그인 성공 후 어떤 방식으로 상태를 유지할지 적기
- 세션 만료 시 사용자에게 어떤 안내를 줄지 정하기
- 로그아웃 시 세션을 어떻게 정리할지도 함께 요청하기
- 보호된 페이지 접근 제어까지 포함하기

/>

## 복붙 가능한 프롬프트 예시

### 1. 기본 세션 유지

<PromptCodeBlock>
로그인 성공 후 세션 기반으로 인증 상태를 유지해주세요.
사용자가 페이지를 이동하거나 새로고침해도 로그인 상태가 유지되게 하고, 로그아웃하면 세션을 즉시 정리해주세요.
비로그인 상태에서 보호된 페이지에 접근하면 로그인 페이지로 보내주세요.
</PromptCodeBlock>

### 2. 세션 만료 처리

<PromptCodeBlock>
세션이 만료되면 사용자가 갑자기 튕긴 것처럼 느끼지 않게 처리해주세요.
만료 안내 메시지를 보여주고, 다시 로그인 버튼을 제공해주세요.
가능하면 로그인 후 이전에 보던 페이지로 돌아오게 해주세요.
</PromptCodeBlock>

### 3. 관리자 페이지 보호

<PromptCodeBlock>
관리자 페이지는 세션이 있는 사용자만 접근할 수 있게 해주세요.
세션이 없거나 만료된 경우에는 로그인 페이지로 보내고, 권한이 없는 경우에는 접근 불가 안내 화면을 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="세션 만료 경험을 빼먹으면 실제 사용성이 크게 떨어집니다">
로그인 성공만 설계하고 만료 후 흐름을 빼면, 사용자는 갑자기 로그아웃된 것처럼 느끼게 됩니다.
</Callout>

## 구현 체크리스트

- 로그인 후 세션이 유지되는가
- 보호된 페이지 접근 제어가 있는가
- 로그아웃 시 세션이 정리되는가
- 세션 만료 후 사용자 안내와 재로그인 흐름이 있는가
- 이전에 보던 페이지로 복귀할 수 있는가

## 자주 헷갈리는 개념 비교

### 세션 vs 토큰

- 세션: 서버가 인증 상태를 중심으로 관리한다
- 토큰: 클라이언트가 인증 문자열을 들고 요청마다 전달한다

### 세션 vs 인증 흐름

- 세션: 로그인 상태를 유지하는 방식
- 인증 흐름: 로그인, 만료, 권한 부족까지 포함한 전체 과정

### 세션 vs 쿠키

- 세션: 서버가 인증 상태를 관리하는 방식
- 쿠키: 그 세션 식별 정보를 브라우저와 주고받는 전달 수단 중 하나
