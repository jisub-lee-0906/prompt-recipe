# 정렬 API

> 한 줄 정의: 정렬 API는 같은 결과 집합을 어떤 기준과 순서로 반환할지 서버에서 제어하는 API 설계 방식입니다.

## 왜 중요한가

프론트엔드에서 정렬 UI를 만들어도 서버가 어떤 정렬 기준을 받을지 모르면 실제 결과는 바뀌지 않습니다. AI IDE에게 정렬 API를 명시하면 허용 가능한 정렬 기준, 기본값, 잘못된 정렬 값 처리까지 함께 정리할 수 있습니다.

## 언제 쓰는가

- 목록 API에서 최신순, 가나다순, 인기순 같은 정렬이 필요할 때
- 검색 결과와 필터 결과를 다양한 기준으로 보여줘야 할 때
- 관리자 테이블에서 열 기준 정렬이 필요한 경우

## 언제 쓰지 말아야 하는가

- 결과 수가 적고 프론트엔드 정렬만으로도 충분할 때
- 정렬 기준이 사실상 하나뿐이라 별도 파라미터가 과한 경우

<Callout type="tip" title="정렬 API는 허용 기준을 제한해야 안전합니다">
임의 필드명을 그대로 받아 정렬하면 예측하기 어렵고 보안·성능 문제도 생길 수 있습니다. 허용 가능한 정렬 옵션을 미리 정하는 편이 좋습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

정렬 API를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 정렬 기준을 허용할지
- 기본 정렬이 무엇인지
- 오름차순과 내림차순을 둘 다 지원할지
- 잘못된 값 처리 기준이 있는지

<PromptCodeBlock>
문서 목록 API가 `latest`, `title`, `popular` 정렬 기준을 받을 수 있게 해주세요.
기본값은 `latest`로 두고, 잘못된 정렬 값이 들어오면 표준화된 에러 응답을 내려주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 API에서 관련도순, 최신순, 제목순 정렬을 지원해주세요.
프론트엔드 정렬 UI와 맞물릴 수 있게 허용 가능한 값 목록을 명확히 정의해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 사용자 목록 API는 `createdAt`, `lastLoginAt`, `name` 기준 정렬을 지원해주세요.
정렬 방향은 `asc`, `desc`를 받을 수 있게 하고, 없는 필드명은 허용하지 말아주세요.
</PromptCodeBlock>

<Callout type="warning" title="정렬 기준을 무제한으로 열어두면 구현과 운영이 모두 복잡해집니다">
허용되는 기준을 명확히 정해야 프론트엔드 UI도 단순해지고, 서버도 안전하게 제어할 수 있습니다.
</Callout>

## 구현 체크리스트

- 허용 가능한 정렬 기준이 정의되어 있는가
- 기본 정렬 기준이 있는가
- 방향 값 처리 기준이 있는가
- 잘못된 값에 대한 에러 응답이 있는가
- 필터와 페이지네이션과 함께 써도 구조가 유지되는가

## 자주 헷갈리는 개념 비교

### 정렬 API vs 정렬 UI

- 정렬 API는 서버 인터페이스입니다.
- 정렬 UI는 사용자가 정렬 기준을 바꾸는 화면입니다.

### 정렬 API vs 필터링 API

- 정렬 API는 결과 순서를 바꿉니다.
- 필터링 API는 결과 집합 자체를 줄입니다.

### 정렬 API vs 페이지네이션 API

- 정렬 API는 반환 순서를 정합니다.
- 페이지네이션 API는 반환 범위를 나눕니다.
