# 토큰

> 한 줄 정의: 토큰은 사용자의 인증 정보를 담아 클라이언트와 서버 사이에서 전달하는 문자열 기반 자격 증명입니다.

## 왜 중요한가

사용자가 "로그인 상태 유지되게 해줘"라고 말할 때, 어떤 시스템은 세션을 쓰고 어떤 시스템은 토큰을 씁니다. 이 차이를 모르고 요청하면 로그인 화면만 생기고, 실제 인증 유지 방식은 빠진 결과가 나올 수 있습니다.

토큰은 특히 API 중심 구조나 여러 클라이언트 환경을 다룰 때 자주 등장하는 핵심 개념입니다.

## 언제 쓰는가

- API 요청마다 인증 정보를 함께 보내야 할 때
- 웹과 앱 등 여러 클라이언트가 같은 인증 구조를 공유할 때
- 세션 대신 토큰 기반 인증 전략을 쓸 때

## 언제 쓰지 말아야 하는가

- 서버 중심 세션 인증이 더 적합한 구조일 때
- 공개 페이지처럼 인증 자체가 필요 없는 경우

<Callout type="info" title="토큰은 로그인 성공 화면이 아니라 요청마다 인증을 전달하는 방식입니다">
사용자가 로그인한 뒤 이후 요청에서 어떤 자격 증명을 들고 다니는지까지 같이 생각해야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "로그인 토큰 발급되게 해줘"
- "API 요청할 때 인증 붙여줘"
- "JWT로 로그인 유지해줘"

이 요청에는 저장 위치, 만료 시점, 만료 후 처리, 갱신 전략이 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 요청에 토큰을 붙일지 적기
- 토큰 만료 시 사용자 경험을 정하기
- 재로그인 또는 토큰 갱신 흐름을 함께 요청하기
- 로그아웃 시 정리 방식도 포함하기

## 복붙 가능한 프롬프트 예시

### 1. 토큰 기반 API 인증

<PromptCodeBlock>
로그인 성공 후 토큰 기반으로 인증 상태를 유지해주세요.
보호된 API 요청에는 토큰을 함께 보내고, 로그아웃 시에는 저장된 토큰도 정리해주세요.
비로그인 사용자가 보호된 페이지에 접근하면 로그인 페이지로 보내주세요.
</PromptCodeBlock>

### 2. 토큰 만료 처리

<PromptCodeBlock>
토큰이 만료되면 사용자가 갑자기 로그아웃된 것처럼 느끼지 않게 처리해주세요.
만료 안내 메시지를 보여주고, 다시 로그인 버튼을 제공해주세요.
가능하면 현재 보고 있던 페이지로 다시 돌아올 수 있게 해주세요.
</PromptCodeBlock>

### 3. 모바일 앱용 토큰 흐름

<PromptCodeBlock>
웹과 모바일 앱이 함께 쓰는 토큰 기반 인증 흐름을 설계해주세요.
로그인 성공 후 access token과 refresh token을 어떻게 다룰지 정리하고, access token 만료 시에는 refresh 흐름을 거친 뒤 실패하면 다시 로그인하게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="토큰 발급만 만들고 만료 후 처리를 빼면 실제 서비스에서 바로 문제가 됩니다">
로그인 성공 흐름만큼 만료, 재로그인, 로그아웃 처리도 같이 설계해야 사용성이 안정적입니다.
</Callout>

## 구현 체크리스트

- 어떤 요청에 토큰을 붙이는지 정해져 있는가
- 로그아웃 시 토큰 정리가 되는가
- 만료 후 안내와 재로그인 흐름이 있는가
- 보호된 API와 페이지 접근 제어가 있는가
- 갱신 전략이 필요한지 판단되어 있는가

## 자주 헷갈리는 개념 비교

### 토큰 vs 세션

- 토큰: 클라이언트가 인증 문자열을 보관하고 요청마다 전달한다
- 세션: 서버가 인증 상태를 중심으로 유지한다

### 토큰 vs 인증 흐름

- 토큰: 인증 상태를 전달하는 방식
- 인증 흐름: 로그인, 만료, 권한 부족까지 포함한 전체 과정

### 토큰 vs 쿠키 저장

- 토큰: 인증 정보 자체
- 쿠키 저장: 그 토큰을 보관하거나 전달하는 수단 중 하나
