# 인증 흐름

> 한 줄 정의: 인증 흐름은 사용자가 누구인지 확인하고, 어떤 기능까지 사용할 수 있는지 판단하는 전체 과정입니다.

## 왜 중요한가

AI IDE에게 "로그인 기능 붙여줘"라고만 요청하면 로그인 화면까지만 구현되고 끝나는 경우가 많습니다. 하지만 실무의 인증 흐름은 로그인 성공 이후, 비로그인 접근, 세션 만료, 로그아웃, 권한 부족 처리까지 포함합니다.

## 언제 쓰는가

- 로그인한 사용자만 기능을 사용할 수 있을 때
- 사용자별로 다른 데이터를 보여줘야 할 때
- 관리자/일반 사용자 권한을 구분해야 할 때

## 언제 쓰지 말아야 하는가

- 로그인 성공 케이스만 있을 때
- 비로그인 접근 시 처리 방식이 없을 때
- 세션 만료와 권한 부족이 구분되지 않을 때

<Callout type="warning" title="로그인 화면만 있다고 인증 흐름이 완성되는 것은 아닙니다">
로그인 이후의 이동, 만료 처리, 권한 부족, 로그아웃까지 설계해야 실제 서비스에서 동작합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "로그인한 사람만 보이게 해줘."
- "관리자만 수정 가능하게 해줘."
- "로그인 안 하면 막아줘."

이 요청은 보통 접근 차단만 떠올리지만, 실제로는 어디로 보내는지, 원래 보던 화면으로 돌아오는지, 세션이 끊겼을 때 무엇을 보여주는지까지 정해야 합니다.

## 더 좋은 요청으로 바꾸는 방법

좋은 요청은 아래 요소를 포함합니다.

- 누가 접근 가능한지
- 비로그인일 때 무엇을 보여줄지
- 로그인 후 어디로 돌아갈지
- 세션 만료 시 어떻게 처리할지
- 권한 부족 상태를 어떻게 구분할지

<PromptCard
  badPrompt="로그인한 사용자만 즐겨찾기 가능하게 해줘."
  goodPrompt="로그인한 사용자만 문서 즐겨찾기 버튼을 사용할 수 있게 인증 흐름을 설계해주세요. 비로그인 상태에서는 로그인 유도 메시지를 보여주고, 로그인 후에는 원래 보던 문서로 자연스럽게 돌아오게 해주세요."
/>

## 복붙 가능한 프롬프트

### 1. 비로그인 접근 차단 흐름

<PromptCodeBlock>
로그인한 사용자만 문서 즐겨찾기 버튼을 사용할 수 있게 인증 흐름을 설계해주세요.
비로그인 상태에서는 로그인 유도 메시지를 보여주고, 로그인 후에는 원래 보던 문서로 자연스럽게 돌아오게 해주세요.
세션 만료 시에는 다시 로그인해야 한다는 안내도 함께 제공해주세요.
로그인 유도 전 현재 문서 위치를 기억해 복귀 경로가 유지되게 해주세요.
</PromptCodeBlock>

### 2. 관리자 전용 권한 흐름

<PromptCodeBlock>
관리자만 문서 수정 페이지에 접근할 수 있게 해주세요.
일반 사용자가 접근하면 403 성격의 안내 화면을 보여주고, 관리자에게만 수정 폼과 저장 버튼이 보이게 해주세요.
권한 정보는 서버에서 먼저 확인하고, 프론트엔드에서도 버튼 노출을 한 번 더 제어해주세요.
</PromptCodeBlock>

<Callout type="tip" title="인증과 권한은 분리해서 생각하는 편이 좋습니다">
로그인 여부를 확인하는 것과, 로그인한 사용자가 무엇을 할 수 있는지는 서로 다른 문제입니다.
</Callout>

<Callout type="info" title="좋은 인증 흐름 요청은 막는 조건보다 복귀 경로가 더 중요합니다">
비로그인 사용자를 막는 것만 적으면 로그인 후 경험이 끊기기 쉽습니다. 원래 보던 화면으로 돌아가는지, 세션 만료 뒤 무엇을 해야 하는지까지 적어야 흐름이 완성됩니다.
</Callout>

## 구현 체크리스트

- 비로그인 사용자의 접근 경로가 정의되어 있는가
- 로그인 후 원래 페이지 복귀 흐름이 있는가
- 세션 만료 시 안내와 재로그인이 자연스러운가
- 권한 부족과 비로그인 상태가 구분되어 있는가
- 프론트 노출 제어와 서버 검증이 함께 고려되었는가

## 자주 헷갈리는 개념 비교

### 인증 vs 권한

- 인증: 이 사용자가 누구인지 확인
- 권한: 이 사용자가 무엇을 할 수 있는지 결정

### 세션 vs 토큰

- 세션: 서버 중심 로그인 상태 유지
- 토큰: 문자열 기반 자격 증명 전달 방식

### 비로그인 처리 vs 403 처리

- 비로그인: 로그인 유도
- 403: 로그인은 했지만 권한이 없음

### 인증 흐름 vs 로그인 화면

- 인증 흐름: 로그인 전후와 예외 상태를 모두 포함한 전체 절차
- 로그인 화면: 그 절차 안의 첫 진입 화면 하나
