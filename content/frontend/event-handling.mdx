# 이벤트 처리

> 한 줄 정의: 이벤트 처리는 사용자의 행동을 감지하고 그에 맞는 UI 변화나 로직 실행으로 연결하는 프론트엔드 기본 패턴입니다.

## 왜 중요한가

버튼이 눌렸을 때 모달이 열리고, 입력값이 바뀌면 검증이 돌아가고, 폼을 제출하면 저장 요청이 실행됩니다. 이런 연결이 빠지면 화면은 예뻐 보여도 실제로는 작동하지 않습니다. AI IDE에게 단순히 "클릭되게 해줘"라고 하는 대신 어떤 행동이 어떤 결과를 만들어야 하는지까지 요청해야 제대로 구현됩니다.

## 언제 쓰는가

- 버튼 클릭으로 모달, 드롭다운, 토스트를 열거나 닫을 때
- 입력창 값 변경에 따라 검증, 검색, 필터링이 동작할 때
- 폼 제출 시 저장, 삭제, 전송 같은 액션이 실행될 때

## 언제 쓰지 말아야 하는가

- 상호작용이 전혀 없는 정적 콘텐츠 화면일 때
- CSS 상태만으로 충분한 단순 hover 효과까지 자바스크립트 이벤트로 처리하려 할 때

<Callout type="tip" title="이벤트 처리 문서는 행동과 결과를 쌍으로 써야 합니다">
`버튼 클릭 시 모달 열기`처럼 어떤 행동이 어떤 결과를 만드는지 함께 적어야 AI IDE가 빈 인터랙션이 아닌 실제 동작을 만듭니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

이벤트 처리를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 이벤트가 시작점인지
- 성공, 실패, 진행 중 상태가 어떻게 바뀌는지
- 중복 클릭이나 중복 제출을 막아야 하는지
- 결과를 토스트, 인라인 메시지, 화면 전환 중 무엇으로 보여줄지

<PromptCodeBlock>
삭제 버튼을 클릭하면 확인 모달이 열리고, 취소를 누르면 닫히며, 삭제를 누르면 버튼이 로딩 상태로 바뀐 뒤 성공 토스트를 보여주세요.
실패하면 에러 메시지를 보여주고 모달은 유지해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
이메일 입력창에서 사용자가 입력할 때마다 형식을 검사해주세요.
형식이 맞지 않으면 입력 아래에 즉시 에러 문구를 보여주고, 형식이 맞으면 에러를 지워주세요.
다만 키를 누를 때마다 과도하게 검증하지 않도록 약간의 지연도 넣어주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 버튼을 누르거나 Enter를 입력하면 검색이 실행되게 해주세요.
검색 중에는 버튼을 비활성화하고, 완료되면 결과 목록으로 스크롤을 이동시켜주세요.
검색 실패 시에는 화면 상단에 다시 시도할 수 있는 에러 배너를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="이벤트가 많아질수록 상태 정의가 같이 필요합니다">
클릭, 입력, 제출이 겹치면 어떤 상태에서 무엇이 가능한지 먼저 정해야 합니다. 그렇지 않으면 중복 실행이나 엉뚱한 UI 전환이 쉽게 생깁니다.
</Callout>

## 구현 체크리스트

- 어떤 이벤트가 시작점인지 명확한가
- 성공, 실패, 진행 중 상태가 정의되어 있는가
- 중복 클릭과 중복 제출을 막는가
- 사용자에게 즉시 피드백을 보여주는가
- 이벤트 결과가 상태 관리와 자연스럽게 연결되는가

## 자주 헷갈리는 개념 비교

### 이벤트 처리 vs 상태 관리

- 이벤트 처리는 무엇이 시작되는지를 다룹니다.
- 상태 관리는 그 결과가 어떻게 저장되고 바뀌는지를 다룹니다.

### 이벤트 처리 vs 폼 검증

- 이벤트 처리는 클릭, 입력, 제출 같은 행동 전체를 다룹니다.
- 폼 검증은 그중 입력값 유효성 확인에 집중합니다.

### 이벤트 처리 vs 조건부 렌더링

- 이벤트 처리는 변화를 일으킵니다.
- 조건부 렌더링은 그 변화에 따라 무엇을 보여줄지 결정합니다.
