# 정적 사이트 생성

> 한 줄 정의: 정적 사이트 생성은 페이지를 빌드 시점에 미리 HTML로 만들어 두고 배포하는 방식입니다.

## 왜 중요한가

문서 사이트처럼 자주 바뀌지 않는 콘텐츠는 정적 생성과 아주 잘 맞습니다. 요청이 들어올 때마다 서버에서 HTML을 만들 필요가 없고, 배포도 단순해집니다. AI IDE에게 "정적으로 만들어줘"라고만 하는 것보다 SSG라고 명확히 말하면 경로 생성, 메타데이터, 404 처리 같은 구현이 훨씬 정확해집니다.

## 언제 쓰는가

- 문서 사이트, 블로그, 마케팅 페이지처럼 콘텐츠 변경 주기가 느릴 때
- 로컬 MDX나 CMS 데이터로 미리 페이지를 생성할 수 있을 때
- 빠른 응답 속도와 단순한 배포 구조가 중요할 때

## 언제 쓰지 말아야 하는가

- 요청마다 개인화된 데이터를 보여줘야 할 때
- 초 단위로 자주 바뀌는 실시간 데이터가 핵심일 때
- 로그인 상태에 따라 페이지 내용이 크게 달라지는 경우가 많을 때

<Callout type="tip" title="문서 사이트는 SSG와 궁합이 매우 좋습니다">
로컬 MDX 파일 기반 콘텐츠는 정적 생성과 특히 잘 맞습니다. 빌드 때 모든 경로를 미리 만들고 배포하면 성능과 운영 단순성이 모두 좋아집니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

SSG를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 데이터를 기준으로 경로를 만들지
- 동적 경로를 빌드 때 모두 수집할 수 있는지
- 존재하지 않는 경로를 어떻게 처리할지
- 메타데이터도 같이 정적으로 만들지

<PromptCodeBlock>
MDX 문서들을 빌드 시점에 정적으로 생성해주세요.
generateStaticParams로 모든 문서 경로를 미리 만들고, DB 없이 로컬 파일만 읽어서 페이지를 생성하게 해주세요.
존재하지 않는 경로는 404로 처리해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 상세 페이지를 정적 생성으로 구현해주세요.
카테고리와 slug 목록을 빌드 시점에 수집하고, frontmatter를 기반으로 SEO 메타데이터도 함께 생성해주세요.
빌드 단계에서 잘못된 frontmatter가 있으면 바로 실패하게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 사이트를 100% 정적 배포 기준으로 정리해주세요.
검색 인덱스도 로컬 메타데이터로 만들고, 런타임 API 없이 동작하게 해주세요.
페이지 수가 늘어나도 경로 생성이 안정적으로 유지되게 구조를 정리해주세요.
</PromptCodeBlock>

<Callout type="warning" title="실시간 데이터와 개인화가 많다면 SSG만으로는 부족할 수 있습니다">
정적 생성은 빠르고 단순하지만 모든 상황의 만능 해법은 아닙니다. 요청마다 바뀌는 데이터가 중요하면 다른 렌더링 전략을 함께 검토해야 합니다.
</Callout>

## 구현 체크리스트

- 빌드 시 모든 경로를 수집하는가
- 콘텐츠 소스가 정적 파일 구조와 잘 맞는가
- 404와 메타데이터가 함께 처리되는가
- 빌드 단계 검증이 포함되는가
- 런타임 API 없이도 필요한 데이터가 준비되는가

## 자주 헷갈리는 개념 비교

### SSG vs SSR

- SSG는 빌드 시점에 HTML을 만듭니다.
- SSR은 요청 시점에 HTML을 만듭니다.

### SSG vs CSR

- SSG는 초기 HTML이 이미 준비되어 있습니다.
- CSR은 브라우저에서 화면을 조립합니다.

### SSG vs 데이터 페칭

- SSG는 렌더링 시점 전략입니다.
- 데이터 페칭은 어떤 데이터를 어디서 읽어오는지에 관한 개념입니다.
