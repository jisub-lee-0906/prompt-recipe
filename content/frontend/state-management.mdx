# 상태 관리

> 한 줄 정의: 상태 관리는 화면에 영향을 주는 값을 어디에 두고, 어떻게 바꾸고, 어떤 범위까지 공유할지를 정하는 일입니다.

## 왜 중요한가

비개발자가 AI IDE에게 "필터 바꾸면 목록도 바뀌게 해줘"라고 요청할 때, 사실은 단순 UI 변경이 아니라 상태 변화와 데이터 갱신 흐름을 요구하는 것입니다. "상태 관리"라는 개념을 정확히 쓰면 AI IDE가 값의 출처와 동기화 범위를 함께 고려하게 됩니다.

## 언제 쓰는가

- 탭 선택 상태
- 모달 열림 여부
- 입력값
- 로딩 여부
- 필터나 정렬 기준
- 서버 응답 결과와 연결된 화면 표시

## 언제 쓰지 말아야 하는가

- 모든 값을 전역 상태로 올릴 때
- URL, 폼, UI 상태가 서로 따로 놀 때
- 어떤 값이 진짜 기준인지 정하지 않았을 때

<Callout type="warning" title="상태는 필요한 범위까지만 공유하세요">
공유 범위가 작은 값까지 전역 상태로 만들면 디버깅과 유지보수가 오히려 어려워질 수 있습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "선택한 값 유지되게 해줘."
- "필터 바꾸면 목록도 바로 바뀌게 해줘."
- "새로고침해도 선택 상태 남아 있으면 좋겠어."

이 요청들은 보통 "로컬 상태", "공유 상태", "URL 상태"가 섞여 있습니다.

## 더 좋은 요청으로 바꾸는 방법

좋은 요청은 아래 요소를 포함합니다.

- 어떤 값이 상태인지
- 어느 컴포넌트 범위에서 쓰는지
- URL과 동기화할지
- 서버 데이터 재조회와 연결되는지

## 복붙 가능한 프롬프트

### 1. 필터 상태 + URL 동기화

<PromptCodeBlock>
문서 목록 페이지에서 카테고리 필터 상태를 관리하는 로직을 만들어주세요.
사용자가 필터를 변경하면 즉시 목록이 다시 계산되도록 하고, 현재 선택된 필터는 URL 쿼리와도 동기화해주세요.
초기 진입 시 URL 쿼리가 있으면 그 값을 상태의 기본값으로 사용해주세요.
</PromptCodeBlock>

### 2. 모달 열림 상태 관리

<PromptCodeBlock>
문서 상세 페이지에서 공유 버튼을 누르면 공유 모달이 열리게 해주세요.
열림 여부는 로컬 상태로 관리하고, 닫기 버튼과 ESC 키, 바깥 영역 클릭으로 상태가 false가 되게 해주세요.
모달이 닫히면 포커스가 다시 공유 버튼으로 돌아오게 해주세요.
</PromptCodeBlock>

<Callout type="tip" title="어떤 값이 기준 상태인지 먼저 정하세요">
같은 값을 여러 군데에서 따로 저장하면 동기화 문제가 거의 반드시 생깁니다.
</Callout>

## 구현 체크리스트

- 어떤 값이 상태인지 명확히 구분되어 있는가
- 로컬 상태와 공유 상태의 경계가 분명한가
- URL, 폼, 목록 결과가 일관되게 동기화되는가
- 비동기 로딩 상태와 실패 상태가 함께 설계되어 있는가

## 자주 헷갈리는 개념 비교

### 로컬 상태 vs 전역 상태

- 로컬 상태: 특정 컴포넌트 근처에서만 쓰는 값
- 전역 상태: 여러 화면이나 많은 컴포넌트가 공유하는 값

### UI 상태 vs 서버 상태

- UI 상태: 열림 여부, 선택 탭, 입력 중 텍스트
- 서버 상태: API 응답 결과, 로딩 여부, 재요청 상태

### 상태 관리 vs 데이터 페칭

- 상태 관리: 값의 위치와 흐름을 다룸
- 데이터 페칭: 값을 서버에서 가져오는 과정을 다룸
