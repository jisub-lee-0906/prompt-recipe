# 상태 관리

## 개념 설명

상태는 화면에 영향을 주는 값입니다. 탭 선택 상태, 입력값, 로딩 여부, 모달 열림 여부처럼 UI가 바뀌는 기준이 되는 데이터를 포함합니다.

## 언제 사용하는지

사용자 입력이나 비동기 처리 결과에 따라 화면이 달라질 때 상태 관리가 필요합니다. 로컬 상태로 충분한지, 여러 컴포넌트가 공유해야 하는지에 따라 방식이 달라집니다.

### 사용 시 주의점

모든 값을 전역 상태로 올리면 오히려 흐름이 불분명해집니다. 실제 공유 범위가 좁다면 가까운 컴포넌트 안에 두는 편이 더 명확합니다.

## 실무 맥락 예시

기획자가 "현재 선택된 필터가 바뀌면 목록 결과도 즉시 바뀌어야 한다"고 설명한다면, 단순 UI 변경이 아니라 필터 상태와 리스트 데이터 갱신 흐름을 함께 설계해야 합니다.

## AI에게 요청하는 좋은 프롬프트 예시

문서 목록 페이지에서 카테고리 필터 상태를 관리하는 로직을 만들어주세요. 사용자가 필터를 변경하면 즉시 목록이 다시 계산되도록 하고, 현재 선택된 필터는 URL 쿼리와도 동기화해주세요.
