# 디바운스

> 한 줄 정의: 디바운스는 연속으로 발생하는 이벤트를 잠시 모았다가 마지막 한 번만 실행하는 기법입니다.

## 왜 중요한가

검색 입력이나 자동 저장처럼 키 입력마다 바로 요청을 보내면 성능과 UX가 모두 나빠질 수 있습니다. 디바운스는 이런 과한 호출을 줄여줍니다. AI IDE에게 "입력할 때마다 너무 많이 안 돌게 해줘"보다 디바운스를 명시하면 구현 의도가 더 정확해집니다.

## 언제 쓰는가

- 검색 입력 시 API 호출을 너무 자주 보내고 싶지 않을 때
- 자동 저장이나 실시간 검증이 입력마다 바로 실행되면 부담이 클 때
- 빠르게 연속 입력되는 이벤트를 묶고 싶을 때

## 언제 쓰지 말아야 하는가

- 클릭처럼 즉시 반응이 중요한 이벤트에서
- 입력 직후 바로 결과가 나와야 하는 경우
- 오히려 지연이 사용자 경험을 나쁘게 만드는 상호작용에서

<Callout type="tip" title="디바운스는 검색과 입력형 UI에서 특히 유용합니다">
사용자가 잠깐 멈췄을 때만 실행하면 네트워크 요청과 연산량을 크게 줄일 수 있습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

디바운스를 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 입력이나 이벤트에 적용할지
- 어느 정도 지연 시간을 둘지
- 디바운스 중 이전 결과를 유지할지
- 최소 입력 길이와 함께 쓸지

<PromptCodeBlock>
검색 입력창에는 디바운스를 적용해주세요.
사용자가 타이핑을 멈춘 뒤 300ms 정도 지난 시점에만 검색 API를 호출하고, 그 전까지는 이전 결과를 유지해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 제목 자동 저장 기능에 디바운스를 넣어주세요.
사용자가 입력을 멈춘 뒤 잠시 후에만 저장 요청을 보내고, 저장 중에는 작은 상태 메시지를 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
이메일 형식 검증은 입력할 때마다 바로 실행하지 말고 디바운스로 묶어주세요.
타이핑 중에는 에러를 과하게 깜빡이지 않게 하고, 입력이 멈춘 뒤에만 검증 결과를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="디바운스는 모든 이벤트에 적용하면 안 됩니다">
즉시 반응이 필요한 클릭이나 토글까지 디바운스로 묶으면 오히려 느리고 답답하게 느껴질 수 있습니다.
</Callout>

## 구현 체크리스트

- 어떤 이벤트에 적용하는지 명확한가
- 지연 시간이 UX와 맞는가
- 이전 결과 유지 여부가 정해져 있는가
- 최소 입력 길이 등 다른 조건과 충돌하지 않는가
- 즉시 반응이 필요한 이벤트에는 쓰지 않는가

## 자주 헷갈리는 개념 비교

### 디바운스 vs 쓰로틀

- 디바운스는 마지막 한 번만 실행합니다.
- 쓰로틀은 일정 주기마다 실행합니다.

### 디바운스 vs 레이트 리밋

- 디바운스는 프론트엔드 입력 제어 기법입니다.
- 레이트 리밋은 서버 요청 제한 정책입니다.

### 디바운스 vs 검색 바

- 디바운스는 검색 입력을 다루는 기술 기법입니다.
- 검색 바는 사용자가 입력하는 UI 자체입니다.
