# 컴포넌트

> 한 줄 정의: 컴포넌트는 반복해서 사용할 수 있는 UI와 동작을 하나의 단위로 묶은 프론트엔드 설계 방식입니다.

## 왜 중요한가

비개발자가 AI IDE에게 "이 영역 하나 만들어줘"라고 요청하면, 종종 특정 페이지에 박혀 있는 일회성 코드가 나옵니다. 하지만 "컴포넌트"라고 명확하게 표현하면, 재사용 가능성과 입력값 구조를 고려한 설계를 기대할 수 있습니다.

## 언제 쓰는가

- 같은 버튼, 카드, 배지, 헤더가 여러 화면에서 반복될 때
- 하나의 UI를 독립적으로 이해하고 수정해야 할 때
- 같은 구조에 데이터만 바꿔 여러 번 써야 할 때

## 언제 과하게 분리하면 안 되는가

- 실제로 한 번만 쓰는 UI를 억지로 일반화할 때
- props가 너무 많아져 목적이 흐려질 때
- 한 컴포넌트가 여러 책임을 동시에 질 때

<Callout type="tip" title="좋은 컴포넌트는 책임이 좁고 이름이 분명합니다">
재사용 자체보다, 같은 구조와 책임을 반복해서 쓰는지 먼저 확인하는 것이 더 중요합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "카드 UI 하나 만들어줘."
- "이 부분 공통으로 써."
- "똑같은 박스 여러 군데에 넣자."

이 요청은 보통 "무엇이 바뀌고 무엇이 고정인지"가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

좋은 요청은 아래를 포함합니다.

- 어떤 화면에서 재사용할지
- 무엇을 props로 받을지
- 반응형 요구사항이 있는지
- 클릭 가능한지 여부

<PromptCard
  badPrompt="카드 UI 하나 만들어줘."

/>

## 복붙 가능한 프롬프트

### 1. 문서 카드 컴포넌트

<PromptCodeBlock>
문서 카드 컴포넌트를 만들어주세요.
제목, 설명, 태그 배열, 링크를 props로 받아 재사용할 수 있게 구성해주세요.
카드 전체가 클릭 가능해야 하고, hover 상태도 분명하게 보여주세요.
</PromptCodeBlock>

### 2. 상품 카드 컴포넌트

<PromptCodeBlock>
상품 목록에서 재사용할 수 있는 카드 컴포넌트를 만들어주세요.
썸네일, 제목, 가격, 상태 배지를 props로 받게 하고, 모바일과 데스크톱 모두에서 자연스럽게 보이도록 구성해주세요.
품절 상태일 때는 버튼 비활성화 스타일도 함께 처리해주세요.
</PromptCodeBlock>

<Callout type="warning" title="일회성 페이지 구조를 바로 컴포넌트화하지 마세요">
먼저 반복되는 패턴인지 확인하고, 바뀌는 값이 무엇인지 정리한 뒤 분리하는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 무엇이 고정 구조이고 무엇이 props인지 명확한가
- 페이지 전용 로직이 과하게 섞여 있지 않은가
- 이름만 보고 역할을 이해할 수 있는가
- 모바일과 데스크톱 모두에서 레이아웃이 안정적인가

## 자주 헷갈리는 개념

### 컴포넌트 vs 섹션

- 컴포넌트: 재사용 가능한 UI 단위
- 섹션: 페이지 안의 의미적 구획

### 컴포넌트 vs 페이지

- 컴포넌트: 다른 화면에서도 쓸 수 있음
- 페이지: 라우팅과 데이터 흐름을 포함한 화면 전체
