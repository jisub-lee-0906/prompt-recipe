# 하이드레이션

> 한 줄 정의: 하이드레이션은 서버가 먼저 렌더링한 HTML에 브라우저 자바스크립트를 붙여 클릭, 입력, 상태 변경 같은 상호작용이 가능하게 만드는 과정입니다.

## 왜 중요한가

SSR이나 SSG 화면은 처음엔 HTML로 빨리 보이지만, 하이드레이션이 끝나야 버튼 클릭이나 입력 처리 같은 실제 인터랙션이 동작합니다. AI IDE에게 "SSR로 만들어줘"라고만 말하면 하이드레이션 불일치, 깜빡임, 초기 상태 오류가 생기기 쉬워서 서버와 클라이언트 경계를 함께 지시해야 합니다.

## 언제 쓰는가

- 서버에서 먼저 렌더링한 화면에 클라이언트 상호작용을 붙일 때
- SEO와 초기 로딩 속도는 챙기면서 인터랙티브한 UI도 필요할 때
- 서버 컴포넌트와 클라이언트 컴포넌트를 함께 섞어 쓸 때

## 언제 쓰지 말아야 하는가

- 모든 화면을 무조건 서버 렌더링으로 밀어붙일 때
- 서버와 클라이언트에서 다른 초기 값을 만들어도 괜찮다고 생각할 때
- 단순 정적 정보만 보여주는데 불필요하게 복잡한 인터랙션을 얹을 때

<Callout type="tip" title="하이드레이션은 서버와 브라우저가 같은 첫 화면을 공유해야 안정적입니다">
첫 렌더 결과가 다르면 경고가 나거나 화면이 다시 그려질 수 있습니다. 날짜, 랜덤 값, 브라우저 전용 API는 특히 주의해야 합니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

하이드레이션을 고려한 요청을 할 때는 아래를 같이 말해야 합니다.

- 무엇을 서버에서 먼저 보여줄지
- 어떤 부분이 클라이언트 상호작용이 필요한지
- 서버와 클라이언트 초기 값이 달라질 수 있는 요소가 있는지
- 로딩 중 깜빡임이나 재배치가 허용되는지

<PromptCodeBlock>
문서 검색 페이지는 서버에서 초기 결과 목록을 먼저 렌더링해주세요.
다만 검색 입력, 정렬 변경, 즐겨찾기 토글은 클라이언트에서 즉시 반응해야 합니다.
하이드레이션 경고가 나지 않도록 서버와 클라이언트 초기 값이 같게 유지해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
대시보드 통계 카드는 서버에서 먼저 렌더링하되,
브라우저 크기에 따라 바뀌는 요소는 하이드레이션 이후에만 계산해주세요.
처음 HTML과 클라이언트 첫 렌더가 달라지지 않게 안전한 기본값을 사용해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
로그인 상태에 따라 버튼이 바뀌는 헤더를 구현해주세요.
초기에는 서버가 알고 있는 사용자 상태를 기준으로 렌더링하고,
클라이언트에서 추가 정보가 오더라도 레이아웃이 크게 흔들리지 않게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="브라우저 전용 값은 첫 렌더에서 바로 쓰면 위험합니다">
`window`, `localStorage`, 현재 시간, 랜덤 값에 바로 의존하면 서버 HTML과 클라이언트 렌더 결과가 달라질 수 있습니다.
</Callout>

## 구현 체크리스트

- 서버와 클라이언트 첫 렌더 결과가 같은가
- 브라우저 전용 API 사용 시점이 안전한가
- 초기 로딩 중 레이아웃 점프가 없는가
- 클라이언트 상호작용이 필요한 부분만 분리했는가
- 하이드레이션 경고가 없는가

## 자주 헷갈리는 개념 비교

### 하이드레이션 vs SSR

- SSR은 서버에서 HTML을 만드는 방식입니다.
- 하이드레이션은 그 HTML에 클라이언트 동작을 붙이는 과정입니다.

### 하이드레이션 vs 클라이언트 컴포넌트

- 클라이언트 컴포넌트는 브라우저에서 동작해야 하는 컴포넌트입니다.
- 하이드레이션은 그런 컴포넌트가 서버 HTML 위에서 활성화되는 과정입니다.

### 하이드레이션 vs CSR

- CSR은 처음부터 브라우저에서 UI를 조립합니다.
- 하이드레이션은 이미 있는 서버 HTML을 기반으로 인터랙션을 붙입니다.
