# 무한 스크롤 구현

> 한 줄 정의: 무한 스크롤 구현은 사용자가 목록 끝에 가까워졌을 때 다음 페이지 데이터를 자동으로 불러와 이어 붙이는 프론트엔드 로직입니다.

## 왜 중요한가

콘텐츠 피드, 상품 목록, 댓글 리스트처럼 길게 이어지는 화면에서는 페이지를 계속 넘기기보다 자연스럽게 이어 읽는 경험이 더 중요할 수 있습니다. AI IDE에게 "계속 불러와줘"라고만 말하면 중복 요청, 끝없는 로딩, 스크롤 점프 같은 문제가 생기기 쉬워서 트리거 조건과 종료 조건을 함께 지시해야 합니다.

## 언제 쓰는가

- 피드, 탐색 목록, 검색 결과처럼 사용자가 계속 내려보는 화면일 때
- 페이지 구분보다 연속 소비 경험이 더 중요할 때
- 모바일 중심 서비스에서 터치 흐름을 끊고 싶지 않을 때

## 언제 쓰지 말아야 하는가

- 전체 길이를 파악해야 하거나 특정 위치로 다시 돌아가기 쉬워야 할 때
- 푸터 접근이 중요하거나 현재 위치를 기억해야 할 때
- 결과 수가 적거나 페이지 단위 탐색이 더 명확한 업무형 화면일 때

<Callout type="tip" title="트리거보다 종료 조건이 더 중요합니다">
언제 다음 페이지를 부를지뿐 아니라 언제 더 이상 부르지 않을지를 명확히 정의해야 무한 로딩이 생기지 않습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

무한 스크롤을 요청할 때는 아래를 같이 말해야 합니다.

- 무엇을 기준으로 다음 페이지를 요청할지
- 마지막 페이지 여부를 어떻게 판단할지
- 로딩 중 중복 요청을 막을지
- 실패했을 때 재시도 UI가 필요한지

<PromptCodeBlock>
게시글 목록 하단에 sentinel 요소를 두고, 이 요소가 화면에 보이면 다음 페이지를 자동으로 요청해주세요.
이미 요청 중일 때는 중복 호출하지 말고, 마지막 페이지면 더 이상 호출하지 않게 해주세요.
새 데이터는 기존 목록 아래에 붙이고 하단에 로딩 인디케이터를 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
상품 목록은 무한 스크롤로 구현하되, 필터가 바뀌면 목록과 페이지 상태를 초기화해주세요.
스크롤 중 에러가 나면 인라인 에러 메시지와 다시 시도 버튼을 보여주고,
사용자가 다시 시도하면 마지막 실패 지점부터 이어서 불러오게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
댓글 목록은 무한 스크롤을 쓰되, 새 댓글이 추가되어도 현재 읽던 위치가 갑자기 튀지 않게 해주세요.
추가 로딩은 IntersectionObserver 기반으로 구현하고,
초기 로딩, 추가 로딩, 더 이상 없음 상태를 각각 구분해서 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="페이지네이션 API 설계가 먼저 맞아야 합니다">
프론트엔드만 무한 스크롤로 바꿔도 API가 중복 없는 커서나 페이지 정보를 안정적으로 주지 않으면 구현이 흔들립니다.
</Callout>

## 구현 체크리스트

- 다음 페이지 요청 조건이 명확한가
- 마지막 페이지 종료 조건이 있는가
- 로딩 중 중복 호출을 막는가
- 추가 로딩 오류 처리와 재시도가 있는가
- 필터 변경 시 상태 초기화가 되는가
- 위치 점프 없이 목록이 자연스럽게 이어지는가

## 자주 헷갈리는 개념 비교

### 무한 스크롤 구현 vs 무한 스크롤 UI

- 무한 스크롤 구현은 실제 로딩 로직과 상태 관리입니다.
- 무한 스크롤 UI는 그 경험을 어떤 패턴으로 보여줄지에 더 가깝습니다.

### 무한 스크롤 vs 페이지네이션

- 무한 스크롤은 연속 소비에 강합니다.
- 페이지네이션은 위치 파악과 재방문에 강합니다.

### 무한 스크롤 vs 데이터 페칭

- 데이터 페칭은 데이터를 읽는 일반 개념입니다.
- 무한 스크롤 구현은 그중에서도 추가 페이지를 이어 불러오는 특수 흐름입니다.
