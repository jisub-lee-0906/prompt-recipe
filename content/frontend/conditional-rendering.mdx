# 조건부 렌더링

> 한 줄 정의: 조건부 렌더링은 현재 상태에 따라 어떤 화면 조각을 보여줄지 분기하는 방식입니다.

## 왜 중요한가

실제 서비스는 항상 하나의 화면만 가지지 않습니다. 로딩 중일 수도 있고, 데이터가 없을 수도 있고, 오류가 날 수도 있습니다. AI IDE에게 "목록 보여줘"라고만 요청하면 정상 상태 하나만 구현되기 쉽습니다. 조건부 렌더링을 명시해야 예외 상황까지 포함된 실전 화면이 나옵니다.

## 언제 쓰는가

- 로딩, 에러, 빈 상태, 정상 상태를 나눠 보여줄 때
- 로그인 여부나 권한에 따라 다른 버튼을 보여줄 때
- 데이터 유무에 따라 리스트와 안내 메시지를 전환할 때

## 언제 쓰지 말아야 하는가

- 단순 색상 변화나 hover 같은 표현만 필요한데 구조 자체를 분기하려 할 때
- 조건이 너무 복잡해서 별도 컴포넌트로 분리하는 편이 더 읽기 쉬울 때

<Callout type="info" title="조건부 렌더링은 예외 상황을 설계하는 도구입니다">
정상 화면만 만드는 데서 끝나지 않고, 로딩과 실패와 결과 없음까지 함께 보여줘야 실제 사용자 경험이 완성됩니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

  goodPrompt="목록 페이지에서 데이터를 불러오는 중이면 스켈레톤을 보여주고, 결과가 없으면 빈 상태를 보여주세요. 요청이 실패하면 에러 상태와 다시 시도 버튼을 보여주고, 데이터가 있을 때만 실제 리스트를 렌더링해주세요."

## 더 좋은 요청으로 바꾸는 방법

조건부 렌더링을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 상태가 존재하는지
- 상태 우선순위가 무엇인지
- 각 상태에서 보여줄 UI가 무엇인지
- 상태가 바뀌는 조건이 무엇인지

<PromptCodeBlock>
목록 페이지에서 데이터를 불러오는 중이면 스켈레톤을 보여주고, 결과가 없으면 빈 상태를 보여주세요.
요청이 실패하면 에러 상태와 다시 시도 버튼을 보여주고, 데이터가 있을 때만 실제 리스트를 렌더링해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
헤더 오른쪽 영역은 로그인 상태에 따라 다르게 보여주세요.
로그인 전에는 `로그인` 버튼을, 로그인 후에는 프로필 아바타와 설정 메뉴를 보여주세요.
세션 확인 중에는 잠깐 placeholder를 보여줘서 깜빡이는 느낌이 나지 않게 해주세요.
</PromptCodeBlock>

<PromptCodeBlock>
문서 상세 페이지에서 권한이 없으면 본문 대신 접근 제한 안내를 보여주세요.
권한이 있고 데이터 로딩이 끝났을 때만 본문과 TOC를 보여주세요.
권한 확인 중에는 바로 에러를 띄우지 말고 먼저 로딩 상태를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="조건이 많아질수록 우선순위를 먼저 정해야 합니다">
예를 들어 로딩과 에러, 빈 상태가 겹칠 수 있습니다. 어떤 상태를 먼저 평가할지 정하지 않으면 구현마다 화면이 달라지고 버그도 늘어납니다.
</Callout>

## 구현 체크리스트

- 상태 목록이 먼저 정의되어 있는가
- 각 상태에서 보여줄 UI가 분리되어 있는가
- 로딩, 에러, 빈 상태가 모두 고려되는가
- 조건이 복잡하면 컴포넌트 분리를 검토했는가
- 상태 전환 순서가 일관적인가

## 자주 헷갈리는 개념 비교

### 조건부 렌더링 vs 조건부 스타일

- 조건부 렌더링은 요소 자체를 보여주거나 숨깁니다.
- 조건부 스타일은 같은 요소의 모양만 바꿉니다.

### 조건부 렌더링 vs 상태 관리

- 조건부 렌더링은 무엇을 보여줄지 정합니다.
- 상태 관리는 그 조건 값을 어디서 관리할지 정합니다.

### 조건부 렌더링 vs 에러 상태

- 조건부 렌더링은 구현 방식입니다.
- 에러 상태는 그 방식으로 보여줄 수 있는 하나의 상태입니다.
