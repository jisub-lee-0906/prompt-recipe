# Props

> 한 줄 정의: props는 부모 컴포넌트가 자식 컴포넌트에 데이터와 설정을 전달해 화면을 다르게 표현하게 만드는 입력값입니다.

## 왜 중요한가

컴포넌트를 재사용하려면 어떤 값이 외부에서 들어오고, 어떤 값이 내부에 고정되는지 분명해야 합니다. 이 구분이 없으면 AI IDE는 한 번만 쓰는 UI를 만들기 쉽고, 재사용 가능한 구조로 확장하기 어렵습니다.

props는 컴포넌트 재사용성과 역할 분리를 설명할 때 가장 기본이 되는 개념입니다.

## 언제 쓰는가

- 제목, 설명, 태그처럼 표시 내용이 달라질 때
- 버튼 레이블, 상태, 아이콘처럼 표현 옵션이 바뀔 때
- 같은 구조를 여러 데이터에 재사용하고 싶을 때

## 언제 쓰지 말아야 하는가

- 값이 외부에서 오지 않고 컴포넌트 내부에서만 관리될 때
- 너무 많은 값을 무리하게 전달해 컴포넌트 책임이 흐려질 때

<Callout type="tip" title="props는 바뀌는 값과 고정 구조를 나누는 기준입니다">
무엇이 외부에서 바뀌고, 무엇이 컴포넌트 안에 고정돼야 하는지 먼저 정리하면 설계가 훨씬 쉬워집니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "카드에 제목이랑 설명 넣어줘"
- "버튼 문구 바뀌게 해줘"
- "같은 UI를 재사용 가능하게 해줘"

이 요청에는 어떤 값이 바뀌는지, 어떤 구조는 고정인지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 컴포넌트가 외부에서 받아야 할 값을 나열하기
- 필수 props와 선택 props를 구분하기
- 값에 따라 어떤 UI가 달라지는지도 적기

## 복붙 가능한 프롬프트 예시

### 1. 문서 카드 props 설계

<PromptCodeBlock>
문서 카드 컴포넌트를 만들어주세요.
title, description, tags, href를 props로 받아 재사용할 수 있게 구성하고, 카드 전체를 클릭하면 상세 페이지로 이동하게 해주세요.
태그가 없을 때는 태그 영역을 숨겨주세요.
</PromptCodeBlock>

### 2. 버튼 variant props 설계

<PromptCodeBlock>
버튼 컴포넌트를 만들고 label, variant, disabled를 props로 받게 해주세요.
variant 값에 따라 기본, 보조, 위험 스타일이 바뀌게 하고, disabled일 때는 클릭이 되지 않게 해주세요.
</PromptCodeBlock>

### 3. 배지 컴포넌트 props 설계

<PromptCodeBlock>
배지 컴포넌트를 만들고 text와 tone을 props로 받게 해주세요.
tone 값이 success, warning, neutral일 때 각각 다른 색상 스타일을 적용해주세요.
</PromptCodeBlock>

<Callout type="warning" title="props가 너무 많아지면 컴포넌트 책임을 다시 나눠야 합니다">
입력값이 지나치게 많으면 재사용성이 높아지는 것이 아니라 오히려 무엇을 하는 컴포넌트인지 불분명해질 수 있습니다.
</Callout>

## 구현 체크리스트

- 어떤 값이 props인지 명확한가
- 필수와 선택 입력이 구분되는가
- 값 변화에 따라 UI가 자연스럽게 달라지는가
- props 개수가 과하게 많지 않은가
- 컴포넌트 재사용 목적이 분명한가

## 자주 헷갈리는 개념 비교

### props vs 상태 관리

- props: 외부에서 들어오는 값
- 상태 관리: 내부 또는 공유 상태로 바뀌는 값

### props vs 컴포넌트 children

- props: 명시적으로 전달하는 데이터와 옵션
- children: 컴포넌트 안에 중첩되는 콘텐츠

### props vs 하드코딩된 값

- props: 재사용을 위해 외부에서 바뀔 수 있는 값
- 하드코딩: 해당 컴포넌트 안에 고정된 값
