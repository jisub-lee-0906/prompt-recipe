# 쓰로틀

> 한 줄 정의: 쓰로틀은 연속으로 발생하는 이벤트를 일정 시간 간격마다 한 번만 실행되게 제한하는 기법입니다.

## 왜 중요한가

스크롤, 리사이즈, 마우스 이동처럼 너무 자주 발생하는 이벤트를 그대로 처리하면 성능이 쉽게 나빠집니다. AI IDE에게 "스크롤할 때 너무 많이 안 돌게 해줘"보다 쓰로틀을 명시하면 어느 간격으로 제한할지, 어떤 이벤트에 적용할지 더 정확하게 구현됩니다.

## 언제 쓰는가

- 스크롤 위치 추적, 무한 스크롤 감지, 창 크기 변경 처리에서
- 빠르게 연속 발생하는 이벤트를 일정 주기로만 반응하게 하고 싶을 때
- 실시간으로 계속 반응하되 너무 자주 실행되면 부담이 큰 경우

## 언제 쓰지 말아야 하는가

- 사용자가 멈춘 뒤 마지막 한 번만 처리하면 되는 검색 입력 같은 경우
- 클릭처럼 즉시 반응이 중요한 이벤트에서
- 마지막 상태만 중요해서 디바운스가 더 적절한 경우

<Callout type="tip" title="쓰로틀은 계속 반응하되 빈도를 줄이는 데 적합합니다">
스크롤 위치처럼 연속 업데이트가 필요한 경우에는 디바운스보다 쓰로틀이 더 자연스럽습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

쓰로틀을 요청할 때는 아래를 같이 말해야 합니다.

- 어떤 이벤트에 적용할지
- 어느 정도 간격으로 제한할지
- 실시간 반응이 얼마나 필요한지
- 디바운스와 혼동하지 않는지

<PromptCodeBlock>
문서 페이지에서 TOC 활성 섹션 추적은 쓰로틀로 제어해주세요.
스크롤 이벤트가 너무 자주 실행되지 않게 일정 간격으로만 갱신하고, 사용자가 스크롤할 때는 충분히 부드럽게 반응해야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
리사이즈 이벤트로 레이아웃을 다시 계산하는 로직은 쓰로틀을 적용해주세요.
창 크기를 바꾸는 동안 일정 주기로만 계산하게 해서 렌더링 부담을 줄여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
무한 스크롤 하단 감지 로직은 쓰로틀을 사용해주세요.
스크롤할 때마다 무겁게 계산하지 말고, 일정 간격마다만 다음 페이지 로드 조건을 확인해주세요.
</PromptCodeBlock>

<Callout type="warning" title="쓰로틀과 디바운스를 혼동하면 UX가 달라집니다">
계속 반응해야 하는 이벤트에 디바운스를 쓰면 늦게 느껴질 수 있고, 마지막 값만 중요한 입력에 쓰로틀을 쓰면 불필요한 실행이 남습니다.
</Callout>

## 구현 체크리스트

- 이벤트 성격이 쓰로틀과 맞는가
- 간격이 너무 짧거나 길지 않은가
- 디바운스보다 쓰로틀이 더 적절한가
- 부드러운 사용자 경험을 유지하는가
- 과도한 연산이나 렌더링을 줄이는가

## 자주 헷갈리는 개념 비교

### 쓰로틀 vs 디바운스

- 쓰로틀은 일정 주기마다 실행합니다.
- 디바운스는 마지막 한 번만 실행합니다.

### 쓰로틀 vs 레이트 리밋

- 쓰로틀은 프론트엔드 이벤트 제어 기법입니다.
- 레이트 리밋은 서버 요청 제한 정책입니다.

### 쓰로틀 vs 무한 스크롤 구현

- 쓰로틀은 구현 기법입니다.
- 무한 스크롤 구현은 그 기법을 사용하는 하나의 사용처입니다.
