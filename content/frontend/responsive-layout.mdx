# 반응형 레이아웃

> 한 줄 정의: 반응형 레이아웃은 화면 크기와 기기 조건에 따라 구조, 컬럼 수, 여백, 탐색 방식을 조정하는 설계 방식입니다.

## 왜 중요한가

AI IDE에게 데스크톱 화면만 기준으로 요청하면, 실제 모바일에서는 사이드바가 너무 넓거나 버튼이 누르기 어려운 결과가 나올 수 있습니다. 반응형 레이아웃을 명시해야 여러 화면 크기에서 자연스러운 구조가 나옵니다.

## 언제 쓰는가

- 데스크톱과 모바일에서 같은 서비스를 제공할 때
- 카드 수, 사이드바, 탐색 방식이 화면 크기에 따라 달라질 때
- 문서 사이트, 대시보드, 이커머스처럼 반응형 품질이 중요한 화면에서

## 언제 쓰지 말아야 하는가

- 특정 기기 전용의 내부 도구만 빠르게 만들 때
- 화면 크기별 차이가 거의 없는 단순 페이지일 때

<Callout type="info" title="반응형은 줄어드는 것이 아니라 재구성되는 것입니다">
단순히 폭만 좁히는 것이 아니라, 어떤 요소를 숨기고 어떤 요소를 대체할지까지 함께 설계해야 합니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "모바일에서도 잘 보이게 해줘"
- "반응형으로 만들어줘"
- "작은 화면에서도 안 깨지게 해줘"

이 요청에는 어느 시점에 구조를 바꿀지, 무엇을 숨기고 무엇을 대체할지 같은 기준이 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 데스크톱과 모바일에서 어떤 요소가 달라지는지 적기
- 컬럼 수, 사이드바, 버튼 배치 기준을 적기
- 특정 브레이크포인트에서 어떤 구조로 바뀌는지 요청하기

## 복붙 가능한 프롬프트 예시

### 1. 문서 페이지 반응형 레이아웃

<PromptCodeBlock>
문서 페이지를 반응형 레이아웃으로 구성해주세요.
데스크톱에서는 헤더, 왼쪽 사이드바, 본문, 오른쪽 TOC를 보여주고, 모바일에서는 사이드바와 TOC를 숨긴 뒤 햄버거 메뉴와 본문 중심 구조로 바꿔주세요.
본문 가독성이 너무 좁거나 넓지 않게 최대 폭도 조절해주세요.
</PromptCodeBlock>

### 2. 카드 목록 반응형 레이아웃

<PromptCodeBlock>
카드 목록 페이지를 반응형으로 만들어주세요.
데스크톱에서는 4열, 태블릿에서는 2열, 모바일에서는 1열 카드 구조로 바꿔주세요.
모바일에서는 필터 바를 상단 토글 패널로 바꾸고, 카드 간 여백도 더 넉넉하게 조정해주세요.
</PromptCodeBlock>

### 3. 관리자 테이블 반응형 전환

<PromptCodeBlock>
관리자 사용자 목록 화면을 반응형으로 구성해주세요.
데스크톱에서는 테이블을 유지하되, 모바일에서는 각 사용자를 카드형으로 바꾸고 핵심 정보만 먼저 보이게 해주세요.
긴 표를 그대로 축소하지 말고 모바일에 맞는 구조로 재구성해주세요.
</PromptCodeBlock>

<Callout type="warning" title="모바일에서는 데스크톱 요소를 그대로 축소하면 더 나빠질 수 있습니다">
사이드바, 복잡한 테이블, 긴 필터 바처럼 데스크톱 전용 구조는 모바일에서 다른 패턴으로 대체하는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 화면 크기별 컬럼 수 규칙이 있는가
- 모바일에서 숨기거나 대체할 요소가 정해져 있는가
- 터치 대상 크기가 충분한가
- 본문 최대 폭과 여백이 조절되는가
- 복잡한 데스크톱 UI가 모바일에서 다른 구조로 재해석되는가

## 자주 헷갈리는 개념 비교

### 반응형 레이아웃 vs 반응형 설계

- 반응형 레이아웃: 실제 화면 구조가 어떻게 바뀌는지
- 반응형 설계: 더 넓은 전략과 원칙

### 반응형 레이아웃 vs 레이아웃

- 레이아웃: 공통 구조 자체
- 반응형 레이아웃: 그 구조가 화면 크기에 따라 바뀌는 방식

### 반응형 레이아웃 vs 접근성

- 반응형 레이아웃: 화면 크기 변화 대응
- 접근성: 다양한 입력 방식과 사용 환경 대응
