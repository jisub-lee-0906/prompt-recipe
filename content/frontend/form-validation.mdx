# 폼 검증

> 한 줄 정의: 폼 검증은 사용자가 입력한 값이 요구 조건에 맞는지 확인하고, 잘못된 입력을 이해 가능한 방식으로 안내하는 과정입니다.

## 왜 중요한가

폼 검증은 단순히 제출을 막는 기술이 아니라, 사용자가 실수 없이 작업을 끝낼 수 있게 돕는 UX입니다. 검증이 없으면 잘못된 데이터가 쌓이고, 검증이 거칠면 사용자는 무엇을 고쳐야 하는지 몰라 답답해집니다.

좋은 검증은 문제를 지적하는 것이 아니라, 올바른 입력으로 유도하는 역할을 합니다.

## 언제 쓰는가

- 이메일 형식, 비밀번호 길이, 필수 입력 검사
- 전화번호, 날짜, 숫자 범위 같은 형식 제한
- 제출 전 조건을 만족하는지 확인해야 할 때

## 언제 쓰지 말아야 하는가

- 검증 규칙이 불필요하게 많아 사용성을 해칠 때
- 입력 중 모든 시점에 과한 경고를 띄워 사용자를 방해할 때

<Callout type="tip" title="검증 메시지는 문제와 해결법을 함께 보여줘야 합니다">
틀렸다고만 말하는 것보다 어떤 형식이 필요한지 바로 이해할 수 있게 안내하는 편이 훨씬 좋습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "이메일 검증 넣어줘"
- "필수 입력 막아줘"
- "잘못 쓰면 에러 뜨게 해줘"

이 요청에는 어떤 규칙이 있는지, 언제 검증할지, 어떤 문구로 보여줄지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 규칙을 구체적으로 나열하기
- 실시간 검증인지 제출 시 검증인지 구분하기
- 필드별 에러 메시지를 예시로 적기
- 성공 가능한 입력 상태가 언제인지도 같이 적기

## 복붙 가능한 프롬프트 예시

### 1. 회원가입 폼 검증

<PromptCodeBlock>
회원가입 폼에 이메일과 비밀번호 검증을 넣어주세요.
이메일 형식이 틀리면 즉시 에러 메시지를 보여주고, 비밀번호는 8자 이상일 때만 제출 가능하게 해주세요.
메시지는 사용자가 어떻게 수정해야 하는지 이해할 수 있게 써주세요.
</PromptCodeBlock>

### 2. 필수 입력 검증

<PromptCodeBlock>
필수 입력이 비어 있으면 제출 버튼을 막고, 각 필드 아래에 어떤 입력이 필요한지 설명하는 에러 메시지를 보여주세요.
사용자가 값을 채우면 에러 메시지는 바로 사라지게 해주세요.
</PromptCodeBlock>

### 3. 날짜와 숫자 범위 검증

<PromptCodeBlock>
예약 폼에서 날짜와 인원 수를 검증해주세요.
과거 날짜는 선택할 수 없게 하고, 인원 수는 1명 이상 10명 이하일 때만 제출 가능하게 해주세요.
조건을 벗어나면 필드 아래에 이유를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="모든 검증을 입력 순간마다 강하게 보여주면 오히려 피로합니다">
입력 중 방해가 큰 규칙은 blur 시점이나 제출 시점에 검증하는 편이 더 자연스러울 수 있습니다.
</Callout>

## 구현 체크리스트

- 어떤 규칙이 있는지 명확한가
- 에러 메시지가 해결 방법을 포함하는가
- 실시간 검증과 제출 시 검증이 구분되는가
- 성공 가능한 상태가 명확한가
- 에러 표시가 사용자를 과하게 방해하지 않는가

## 자주 헷갈리는 개념 비교

### 폼 검증 vs 폼

- 폼 검증: 입력값이 올바른지 판단한다
- 폼: 입력과 제출을 포함한 전체 구조다

### 폼 검증 vs 에러 상태

- 폼 검증: 입력 단계에서의 오류 판단
- 에러 상태: 요청 실패나 시스템 오류까지 포함한 더 넓은 개념

### 폼 검증 vs 제어 컴포넌트

- 폼 검증: 규칙을 판단하는 로직
- 제어 컴포넌트: 값을 상태로 관리하는 방식
