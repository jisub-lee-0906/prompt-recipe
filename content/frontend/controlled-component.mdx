# 제어 컴포넌트

> 한 줄 정의: 제어 컴포넌트는 입력값을 컴포넌트 상태와 연결해, 화면에 보이는 값과 변경 로직을 코드에서 직접 관리하는 방식입니다.

## 왜 중요한가

사용자가 "입력값이 바뀌면 버튼 상태도 바뀌게 해줘"라고 요청할 때, 실제 구현에서는 입력값을 읽고 조건에 따라 버튼 비활성화나 에러 메시지를 바꿔야 합니다. 이 연결이 명확하지 않으면 입력과 UI 상태가 쉽게 어긋납니다.

제어 컴포넌트는 폼 상호작용을 단순 입력창이 아니라 상태 기반 흐름으로 바꿔주는 핵심 개념입니다.

## 언제 쓰는가

- 입력값에 따라 버튼 활성화 여부를 바꿔야 할 때
- 실시간 검증이 필요할 때
- 입력 상태를 다른 UI와 함께 연결해야 할 때

## 언제 쓰지 말아야 하는가

- 단순한 기본 입력만 필요한 경우
- 너무 큰 입력 폼에서 매 키 입력마다 상태 관리가 과한 경우

<Callout type="tip" title="입력값을 코드에서 관리하면 UI 반응을 훨씬 세밀하게 설계할 수 있습니다">
버튼 활성화, 에러 문구, 글자 수 카운터처럼 다양한 반응을 입력값 기준으로 안정적으로 연결할 수 있습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "입력하면 바로 반응하게 해줘"
- "값 없으면 버튼 막아줘"
- "입력 내용에 따라 안내문 바뀌게 해줘"

이 요청에는 어떤 값이 어떤 상태 변화를 만드는지, 어느 시점에 반응해야 하는지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 입력값을 기준으로 UI가 바뀌는지 적기
- 언제 버튼이 활성화되는지 조건을 적기
- 입력 중 검증인지 제출 후 검증인지 구분하기
- 다른 UI 요소와 어떤 식으로 연결되는지도 적기

## 복붙 가능한 프롬프트 예시

### 1. 이메일 입력 제어

<PromptCodeBlock>
이메일 입력값을 상태로 제어해주세요.
값이 비어 있지 않고 이메일 형식이 맞을 때만 제출 버튼이 활성화되게 해주세요.
형식이 틀리면 입력 아래에 에러 메시지를 보여주세요.
</PromptCodeBlock>

### 2. 프로필 소개 입력 제어

<PromptCodeBlock>
프로필 소개 입력창을 제어 컴포넌트로 구현해주세요.
최대 160자 제한을 두고, 현재 글자 수를 입력 아래에 보여주세요.
제한을 넘기면 카운터 색상을 경고 스타일로 바꿔주세요.
</PromptCodeBlock>

### 3. 검색 입력 제어

<PromptCodeBlock>
검색 입력창을 제어 컴포넌트로 구현해주세요.
값이 비어 있으면 최근 검색어 영역을 보여주고, 입력이 시작되면 실시간 검색 결과 목록으로 바뀌게 해주세요.
검색어가 너무 짧으면 안내 메시지를 보여주세요.
</PromptCodeBlock>

<Callout type="warning" title="모든 입력을 무조건 실시간 검증하면 피로해질 수 있습니다">
입력 중 계속 경고가 뜨면 사용성이 나빠질 수 있으니, 언제 피드백할지 같이 설계하는 편이 좋습니다.
</Callout>

## 구현 체크리스트

- 입력값이 상태와 연결되어 있는가
- 값 변화에 따라 UI가 바로 반응하는가
- 활성화 조건과 에러 조건이 분리되어 있는가
- 실시간 피드백이 과하지 않은가
- 입력 상태와 다른 UI 요소 연결이 명확한가

## 자주 헷갈리는 개념 비교

### 제어 컴포넌트 vs 폼

- 제어 컴포넌트: 입력값을 상태로 관리하는 방식
- 폼: 입력과 제출을 포함한 전체 구조

### 제어 컴포넌트 vs 폼 검증

- 제어 컴포넌트: 값을 코드에서 제어한다
- 폼 검증: 값이 올바른지 판단한다

### 제어 컴포넌트 vs 상태 관리

- 제어 컴포넌트: 주로 입력 상태에 집중한다
- 상태 관리: 더 넓은 화면 상태까지 포함한다
