# 리스트 렌더링

> 한 줄 정의: 리스트 렌더링은 여러 개의 데이터를 반복 출력해 목록이나 카드 그리드를 만드는 방식입니다.

## 왜 중요한가

문서 목록, 검색 결과, 상품 목록, 알림 목록처럼 실제 서비스 대부분은 하나의 박스가 아니라 반복되는 아이템 집합입니다. AI IDE에게 "목록을 보여줘"라고만 하면 정적인 샘플 몇 개가 들어갈 수 있습니다. 리스트 렌더링을 정확히 요청해야 데이터 기반 화면으로 이어집니다.

## 언제 쓰는가

- 문서, 게시글, 상품, 사용자처럼 여러 항목을 반복 표시할 때
- 카드 그리드, 리스트, 테이블 같은 반복 구조를 만들 때
- 검색이나 필터 결과를 동적으로 다시 그려야 할 때

## 언제 쓰지 말아야 하는가

- 단일 정보 카드 하나만 보여줄 때
- 반복 자체보다 레이아웃 섹션 구성이 더 중요한 페이지일 때

<Callout type="tip" title="리스트 렌더링은 데이터 구조 설명이 같이 있어야 합니다">
아이템 하나에 어떤 필드가 들어가는지, 클릭 시 어디로 이동하는지, 결과가 없을 때 무엇을 보여줄지까지 함께 적어야 안정적인 결과가 나옵니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

리스트 렌더링을 요청할 때는 아래를 같이 말해야 합니다.

- 아이템 하나에 어떤 필드를 보여줄지
- 클릭 시 이동인지, 내부 버튼 액션인지
- 결과가 없을 때 무엇을 보여줄지
- 카드형인지, 행형인지, 테이블형인지

<PromptCodeBlock>
문서 데이터를 카드 형태로 반복 렌더링해주세요.
각 카드에는 제목, 설명, 태그, 마지막 수정일을 보여주고, 카드를 클릭하면 상세 페이지로 이동하게 해주세요.
결과가 없으면 빈 상태를, 로딩 중이면 스켈레톤 카드를 보여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 화면에서 사용자 목록을 테이블 형태로 렌더링해주세요.
각 행에는 이름, 이메일, 역할, 가입일, 상태를 보여주고, 오른쪽 끝에는 더보기 메뉴 버튼을 넣어주세요.
행 수가 많으면 페이지네이션도 함께 붙여주세요.
</PromptCodeBlock>

<PromptCodeBlock>
검색 결과를 리스트로 렌더링해주세요.
아이템마다 제목, 짧은 발췌, 카테고리 배지를 보여주고 검색어가 문서 안 어디에 있는지도 알 수 있게 해주세요.
검색어가 바뀌면 기존 결과를 새 결과로 자연스럽게 교체해주세요.
</PromptCodeBlock>

<Callout type="warning" title="리스트는 결과가 0개일 때의 설계도 함께 필요합니다">
아이템이 있을 때만 생각하면 실제 서비스에서 자주 보이는 빈 상태가 비게 됩니다. 반복 출력 구조일수록 결과 없음, 로딩, 에러까지 함께 설계해야 합니다.
</Callout>

## 구현 체크리스트

- 아이템 하나의 데이터 구조가 명확한가
- 클릭 또는 액션 동작이 일관적인가
- 로딩, 빈 상태, 에러 상태가 같이 정의되어 있는가
- 항목 수가 많을 때 페이지네이션이나 무한 스크롤이 필요한가
- 반복 키나 식별자가 안정적인가

## 자주 헷갈리는 개념 비교

### 리스트 렌더링 vs 카드 레이아웃

- 리스트 렌더링은 데이터를 반복 출력하는 구현 방식입니다.
- 카드 레이아웃은 그 결과를 카드로 배치하는 UI 패턴입니다.

### 리스트 렌더링 vs 데이터 테이블

- 리스트 렌더링은 더 넓은 개념입니다.
- 데이터 테이블은 열과 행이 있는 특정 표현 방식입니다.

### 리스트 렌더링 vs 조건부 렌더링

- 리스트 렌더링은 여러 아이템을 반복 출력합니다.
- 조건부 렌더링은 현재 상태에 따라 무엇을 보여줄지 결정합니다.
