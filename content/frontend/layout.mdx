# 레이아웃

> 한 줄 정의: 레이아웃은 여러 페이지에서 공통으로 유지되는 헤더, 사이드바, 푸터 같은 구조를 재사용하는 방식입니다.

## 왜 중요한가

사용자가 화면을 여러 개 요청할수록 공통으로 유지돼야 하는 영역이 생깁니다. 그런데 이 구조를 먼저 잡지 않으면 페이지마다 헤더와 메뉴가 조금씩 다르게 생겨서 일관성이 쉽게 깨집니다.

레이아웃은 화면 하나를 예쁘게 만드는 개념이 아니라, 여러 화면을 같은 뼈대 위에 올리는 개념입니다.

## 언제 쓰는가

- 헤더, 사이드바, 푸터가 여러 페이지에서 공통일 때
- 문서 사이트, 대시보드, 설정 화면처럼 같은 구조가 반복될 때
- 특정 영역만 페이지마다 바뀌고 나머지는 유지되어야 할 때

## 언제 쓰지 말아야 하는가

- 단일 페이지 랜딩처럼 공통 구조 재사용이 거의 없을 때
- 페이지마다 구조가 전혀 달라 하나의 레이아웃으로 묶기 어려울 때

<Callout type="tip" title="레이아웃은 공통 요소를 한곳에 모아두는 방식입니다">
페이지마다 중복해서 만들기보다 공통 구조를 레이아웃으로 올려두면 유지보수가 쉬워집니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "모든 페이지에 헤더 붙여줘"
- "문서 페이지는 같은 구조로 가자"
- "설정 화면 왼쪽 메뉴는 계속 고정해줘"

이 요청에는 어디까지가 공통 영역인지, 어떤 경로에서 다른 레이아웃을 쓸지, 모바일에서 어떻게 바뀌는지가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 공통 영역과 가변 영역을 구분하기
- 어떤 경로 묶음이 같은 레이아웃을 쓰는지 적기
- 모바일과 데스크톱 차이를 함께 적기
- 레이아웃별 목적을 분리하기

  badPrompt="문서 페이지는 같은 레이아웃으로 해줘."

/>

## 복붙 가능한 프롬프트 예시

### 1. 문서 레이아웃

<PromptCodeBlock>
문서 페이지 전체에 공통 레이아웃을 적용해주세요.
상단에는 고정 헤더를 두고, 데스크톱에서는 왼쪽 사이드바와 오른쪽 TOC를 함께 보여주세요.
모바일에서는 사이드바와 TOC를 숨기고 본문에 집중할 수 있게 해주세요.
</PromptCodeBlock>

### 2. 설정 레이아웃

<PromptCodeBlock>
설정 페이지 묶음에 공통 레이아웃을 적용해주세요.
왼쪽에는 설정 메뉴를 고정하고, 오른쪽 본문 영역만 페이지마다 바뀌게 해주세요.
상단에는 현재 섹션 제목과 저장 상태 표시도 공통으로 유지해주세요.
</PromptCodeBlock>

### 3. 인증 전용 레이아웃

<PromptCodeBlock>
로그인과 회원가입 화면은 메인 서비스 레이아웃과 분리된 인증 전용 레이아웃을 만들어주세요.
헤더와 사이드바 없이 본문 중심 구조로 두고, 브랜드 로고와 간단한 안내 문구만 공통으로 유지해주세요.
</PromptCodeBlock>

<Callout type="warning" title="공통 영역이 많다고 무조건 하나의 레이아웃으로 묶을 필요는 없습니다">
문서, 대시보드, 인증 화면처럼 성격이 크게 다르면 각각 별도 레이아웃으로 나누는 편이 더 안정적입니다.
</Callout>

## 구현 체크리스트

- 공통 영역과 가변 영역이 구분되는가
- 같은 경로 묶음이 같은 구조를 공유하는가
- 모바일과 데스크톱 차이가 반영되는가
- 레이아웃 중복 코드가 줄어드는가
- 화면 성격이 다른 영역은 별도 레이아웃으로 분리되어 있는가

## 자주 헷갈리는 개념 비교

### 레이아웃 vs 컴포넌트

- 레이아웃: 페이지 구조 단위
- 컴포넌트: 더 작은 UI 조각 단위

### 레이아웃 vs 정보 구조

- 레이아웃: 화면 배치 구조
- 정보 구조: 콘텐츠 분류와 연결 구조

### 레이아웃 vs 라우팅

- 레이아웃: 공통 구조를 어떻게 유지할지
- 라우팅: 어떤 경로가 어떤 페이지를 보여줄지
