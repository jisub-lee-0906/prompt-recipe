# 폼

> 한 줄 정의: 폼은 하나 이상의 입력값을 수집하고, 제출하며, 처리 결과를 사용자에게 안내하는 입력 인터페이스 구조입니다.

## 왜 중요한가

실무에서 많은 요청은 결국 폼으로 귀결됩니다. 회원가입, 프로필 수정, 문의 작성처럼 입력이 들어가면 검증, 제출 중 상태, 성공/실패 피드백까지 같이 설계해야 비로소 "완성된 폼"이 됩니다.

폼은 입력창 몇 개를 나열하는 것이 아니라, 사용자가 작업을 끝낼 수 있게 돕는 하나의 흐름입니다.

## 언제 쓰는가

- 회원가입, 로그인, 프로필 수정
- 문의 작성, 피드백 제출
- 설정 저장, 문서 생성, 이름 변경

## 언제 쓰지 말아야 하는가

- 단일 버튼 액션만으로 충분한 경우
- 입력값이 거의 없고 다른 패턴이 더 간단한 경우

<Callout type="warning" title="폼은 입력창 묶음이 아니라 제출 흐름입니다">
입력, 검증, 제출, 성공, 실패까지 포함해서 설계해야 실제 사용 가능한 폼이 됩니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "프로필 수정 폼 만들어줘"
- "문의하기 화면 넣어줘"
- "입력하고 저장되게 해줘"

이 요청에는 필드 구조, 제출 조건, 성공/실패 피드백이 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 필드가 필요한지 먼저 나열하기
- 필수와 선택 입력을 구분하기
- 제출 중, 성공, 실패 상태를 같이 적기
- 제출 후 어떤 화면이나 메시지가 나와야 하는지 적기

## 복붙 가능한 프롬프트 예시

### 1. 프로필 수정 폼

<PromptCodeBlock>
프로필 수정 폼을 만들어주세요.
이름, 자기소개, 저장 버튼으로 구성하고, 저장 중에는 버튼을 비활성화해주세요.
저장 성공 시에는 토스트를 보여주고, 실패 시에는 인라인 에러 메시지를 보여주세요.
</PromptCodeBlock>

### 2. 문의하기 폼

<PromptCodeBlock>
문의하기 폼을 만들어주세요.
제목, 이메일, 문의 내용 필드를 넣고, 필수 입력이 비어 있으면 제출되지 않게 해주세요.
제출 성공 후에는 완료 메시지를 보여주고, 실패 시에는 다시 시도할 수 있게 해주세요.
</PromptCodeBlock>

### 3. 문서 생성 폼

<PromptCodeBlock>
새 문서 생성 폼을 만들어주세요.
제목, 설명, 카테고리, 태그 입력 필드를 두고, 저장 버튼을 누르면 생성 API를 호출하게 해주세요.
생성 중에는 로딩 상태를 보여주고, 성공하면 상세 페이지로 이동하게 해주세요.
</PromptCodeBlock>

<Callout type="tip" title="좋은 폼은 사용자가 지금 어떤 단계에 있는지 알려줍니다">
무엇을 입력해야 하는지, 지금 제출 중인지, 성공했는지 실패했는지가 분명해야 사용자가 불안하지 않습니다.
</Callout>

## 구현 체크리스트

- 필수와 선택 입력이 구분되는가
- 제출 중 상태가 보이는가
- 성공/실패 피드백이 있는가
- 에러 메시지가 이해하기 쉬운가
- 제출 후 다음 행동이 분명한가

## 자주 헷갈리는 개념 비교

### 폼 vs 제어 컴포넌트

- 폼: 입력과 제출을 포함한 전체 구조
- 제어 컴포넌트: 입력값을 상태로 제어하는 방식

### 폼 vs 다이얼로그 입력

- 폼: 더 넓은 입력 흐름
- 다이얼로그 입력: 짧고 간단한 입력 작업

### 폼 vs 설정 패널

- 폼: 제출 단위가 분명한 입력 구조
- 설정 패널: 여러 조정 옵션이 함께 보이는 구조
