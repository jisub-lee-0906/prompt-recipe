# 클라이언트 컴포넌트

> 한 줄 정의: 클라이언트 컴포넌트는 브라우저에서 실행되며 상태, 이벤트, 브라우저 API를 사용해 상호작용을 처리하는 컴포넌트입니다.

## 왜 중요한가

Next.js App Router에서는 모든 UI를 같은 방식으로 만들지 않습니다. 서버에서 렌더링할 부분과 브라우저에서 동작해야 할 부분을 나눠 생각해야 구조와 성능이 안정적입니다. 이 구분이 없으면 불필요하게 무거운 클라이언트 코드가 늘어나거나, 반대로 인터랙션이 동작하지 않는 결과가 나옵니다.

## 언제 쓰는가

- 클릭, 입력, 토글 같은 이벤트 처리가 필요할 때
- `useState`, `useEffect` 같은 훅이 필요할 때
- `navigator`, `window`, `localStorage` 같은 브라우저 API를 써야 할 때

## 언제 쓰지 말아야 하는가

- 정적 텍스트나 단순 서버 렌더링 UI에 굳이 붙일 때
- 클라이언트 상호작용이 없는 큰 레이아웃 전체를 통째로 클라이언트로 바꿀 때

<Callout type="tip" title="클라이언트 컴포넌트는 필요한 최소 범위로 좁히는 편이 좋습니다">
상호작용이 필요한 작은 부분만 클라이언트로 두고, 나머지는 서버에서 렌더링하면 초기 로드 성능과 구조가 더 안정적입니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "복사 버튼 넣어줘"
- "테마 토글 만들어줘"
- "스크롤 따라 하이라이트되게 해줘"

이 요청은 모두 브라우저 상호작용을 포함하지만, 어디까지를 클라이언트 컴포넌트로 둘지 정하지 않으면 구조가 쉽게 흐려집니다.

## 더 좋은 요청으로 바꾸는 방법

- 어떤 부분만 상호작용이 필요한지 적기
- 서버에서 렌더링할 영역과 브라우저에서 동작할 영역을 나누기
- 상태 관리가 필요한 범위를 최소화하기

<PromptCard
  badPrompt="문서 페이지를 클라이언트 컴포넌트로 만들어줘."
  goodPrompt="문서 페이지 전체는 서버 컴포넌트로 유지하고, 복사 버튼과 TOC 스크롤 스파이처럼 브라우저 상호작용이 필요한 부분만 클라이언트 컴포넌트로 분리해주세요."
/>

## 복붙 가능한 프롬프트 예시

### 1. 복사 버튼 클라이언트 컴포넌트

<PromptCodeBlock>
프롬프트 코드 블록은 서버에서 렌더링하되, 복사 버튼만 클라이언트 컴포넌트로 분리해주세요.
버튼 클릭 시 클립보드 복사를 수행하고 성공 토스트를 보여주세요.
본문 텍스트는 서버에서 그대로 보여지게 유지해주세요.
</PromptCodeBlock>

### 2. 테마 토글 클라이언트 컴포넌트

<PromptCodeBlock>
헤더의 테마 토글 버튼만 클라이언트 컴포넌트로 구현해주세요.
현재 테마에 따라 아이콘이 바뀌고, 클릭하면 라이트/다크 모드를 전환하게 해주세요.
헤더 전체를 클라이언트로 바꾸지 말고 토글 버튼만 분리해주세요.
</PromptCodeBlock>

### 3. 검색 모달 클라이언트 컴포넌트

<PromptCodeBlock>
검색 모달은 클라이언트 컴포넌트로 구현해주세요.
Cmd/Ctrl + K 단축키와 입력 상태, 결과 이동은 브라우저에서 처리하고, 검색 데이터 자체는 서버에서 읽은 결과를 주입받아 사용하게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="상호작용이 없는데도 use client를 넓게 붙이면 번들이 불필요하게 커집니다">
인터랙션이 필요한 최소 단위만 클라이언트로 두는 것이 App Router 구조에 더 잘 맞습니다.
</Callout>

## 구현 체크리스트

- 브라우저 API나 상태가 정말 필요한가
- 상호작용 범위만 클라이언트로 분리했는가
- 서버 컴포넌트로 유지할 수 있는 부분을 남겨뒀는가
- hydration 불일치 가능성을 고려했는가
- 상호작용 없는 공통 레이아웃이 불필요하게 클라이언트화되지 않았는가

## 자주 헷갈리는 개념 비교

### 클라이언트 컴포넌트 vs 서버 컴포넌트

- 클라이언트 컴포넌트: 상태, 이벤트, 브라우저 API 처리에 강하다
- 서버 컴포넌트: 데이터 읽기와 정적 렌더링에 강하다

### 클라이언트 컴포넌트 vs CSR

- 클라이언트 컴포넌트: 일부 컴포넌트의 실행 위치 개념
- CSR: 전체 페이지 렌더링 전략에 가까운 개념

### 클라이언트 컴포넌트 vs 인터랙티브 위젯

- 클라이언트 컴포넌트: 구현 경계
- 인터랙티브 위젯: 사용자 경험 관점의 UI 조각
