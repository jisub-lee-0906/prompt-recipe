# 동적 라우팅

> 한 줄 정의: 동적 라우팅은 같은 페이지 템플릿을 유지한 채, URL 파라미터에 따라 서로 다른 콘텐츠를 보여주는 방식입니다.

## 왜 중요한가

기획자가 "문서 상세 페이지 만들어줘"라고 요청할 때, 실제로는 문서 수만큼 파일을 따로 만드는 것이 아니라 하나의 구조를 여러 slug에 맞춰 재사용하는 경우가 많습니다. 이 개념이 없으면 AI IDE는 비슷한 페이지를 여러 개 복제하는 방향으로 흘러가기 쉽습니다.

동적 라우팅을 이해하면 "페이지 여러 개"가 아니라 "반복 가능한 상세 구조"를 요청할 수 있습니다.

## 언제 쓰는가

- 블로그 글, 문서, 상품 상세처럼 같은 구조가 반복될 때
- 카테고리와 slug 기반 상세 페이지가 필요할 때
- 파일 기반 콘텐츠나 API 데이터로 여러 페이지를 만들 때

## 언제 쓰지 말아야 하는가

- 경로 수가 아주 적고 각각 구조가 완전히 다를 때
- 상세 페이지가 아니라 고정 랜딩 페이지 하나만 필요한 경우

<Callout type="info" title="동적 라우팅은 페이지를 여러 개 만드는 것이 아니라 규칙을 만드는 일입니다">
URL에서 어떤 값을 읽고, 그 값으로 어떤 콘텐츠를 찾을지 정리하면 수십 개 페이지를 한 구조로 관리할 수 있습니다.
</Callout>

## 비개발자가 자주 하는 모호한 요청

- "상세 페이지를 slug로 열리게 해줘"
- "문서별 페이지가 자동으로 생기게 해줘"
- "상품 ID마다 페이지 나오게 해줘"

이 요청에는 URL 구조, 없는 경로 처리, 데이터 소스가 빠져 있습니다.

## 더 좋은 요청으로 바꾸는 방법

- URL 구조를 먼저 적기
- 어떤 데이터 소스를 읽는지 적기
- 없는 경로를 어떻게 처리할지 적기
- 정적 생성인지 요청 시 생성인지도 함께 정하기

## 복붙 가능한 프롬프트 예시

### 1. 문서 상세 동적 라우팅

<PromptCodeBlock>
문서 상세 페이지를 /docs/[category]/[slug] 구조의 동적 라우팅으로 만들어주세요.
로컬 MDX 파일을 기준으로 category와 slug를 읽어 페이지를 정적으로 생성하고, 존재하지 않는 문서는 404를 보여주세요.
사이드바와 브레드크럼도 현재 경로와 연결되게 해주세요.
</PromptCodeBlock>

### 2. 상품 상세 동적 라우팅

<PromptCodeBlock>
상품 상세 페이지를 /products/[productId] 구조의 동적 라우팅으로 만들어주세요.
목록 페이지에서 상품 카드를 클릭하면 해당 productId 상세로 이동하게 하고, 잘못된 ID면 안내 문구가 있는 404 화면을 보여주세요.
</PromptCodeBlock>

### 3. 카테고리별 템플릿 재사용

<PromptCodeBlock>
문서 카테고리별 상세 페이지를 하나의 동적 템플릿으로 재사용해주세요.
URL은 /docs/[category]/[slug] 형태로 유지하고, category에 따라 상단 배지와 관련 문서 목록만 다르게 보여주세요.
본문 구조는 동일한 템플릿을 쓰게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="동적 라우팅은 404 처리까지 포함해서 설계해야 합니다">
존재하지 않는 slug나 잘못된 경로가 들어왔을 때의 처리가 빠지면 사용자 경험이 바로 어색해집니다.
</Callout>

## 구현 체크리스트

- URL 파라미터 구조가 명확한가
- 어떤 데이터 소스를 읽는지 정해져 있는가
- 없는 경로는 404로 처리하는가
- 목록 페이지와 상세 페이지 연결이 자연스러운가
- 정적 생성 또는 요청 시 생성 방식이 분명한가

## 자주 헷갈리는 개념 비교

### 동적 라우팅 vs 라우팅

- 라우팅: 전체 경로 체계를 설계하는 개념
- 동적 라우팅: 경로 일부를 파라미터로 처리하는 방식

### 동적 라우팅 vs SSG

- 동적 라우팅: 경로 구조를 어떻게 표현할지
- SSG: 그 경로를 빌드 시점에 어떻게 생성할지

### 동적 라우팅 vs 검색 결과 페이지

- 동적 라우팅: 파라미터 기반 상세 구조
- 검색 결과 페이지: 목록 조건에 따라 바뀌는 결과 화면
