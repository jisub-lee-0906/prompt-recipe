# CSR

> 한 줄 정의: CSR은 브라우저가 자바스크립트를 실행해 화면을 조립하는 렌더링 방식입니다.

## 왜 중요한가

상호작용이 많은 화면이나 브라우저 상태 중심 화면은 CSR이 자연스럽습니다. 하지만 무조건 CSR로 가면 초기 로딩과 SEO 측면에서 손해를 볼 수도 있습니다. AI IDE에게 CSR이 필요한 이유를 분명히 말해야 다른 렌더링 전략과 혼동되지 않습니다.

## 언제 쓰는가

- 브라우저 상태와 상호작용이 중심인 화면일 때
- 로그인 후 대시보드처럼 SEO보다 조작성이 중요한 화면일 때
- 클라이언트에서 즉시 상태를 바꾸며 작업해야 할 때

## 언제 쓰지 말아야 하는가

- 정적 문서나 SEO가 중요한 페이지일 때
- 서버에서 미리 만들 수 있는 콘텐츠 화면일 때
- 초기 HTML이 없으면 사용자 경험이 크게 나빠질 때

<Callout type="tip" title="CSR은 상호작용이 핵심일 때 강합니다">
복잡한 필터 조합, 실시간 입력 반응, 브라우저 전용 API 사용이 많다면 CSR이 더 자연스러운 선택일 수 있습니다.
</Callout>

## 더 좋은 요청으로 바꾸는 방법

CSR을 요청할 때는 아래를 같이 말해야 합니다.

- 왜 브라우저 조립이 필요한지
- 어떤 상호작용이 중요한지
- SEO가 덜 중요한지
- 초기 로딩보다 조작 반응이 중요한지

<PromptCodeBlock>
로그인 후 대시보드 위젯 화면은 CSR로 구성해주세요.
브라우저에서 사용자 조작에 따라 위젯 배치와 필터 상태가 즉시 바뀌어야 하고, SEO보다 상호작용이 더 중요합니다.
</PromptCodeBlock>

<PromptCodeBlock>
문서 실습 샌드박스 화면은 CSR로 구현해주세요.
사용자가 입력한 프롬프트와 옵션에 따라 즉시 결과 패널이 바뀌어야 하고, 브라우저 상태를 적극적으로 활용해야 합니다.
</PromptCodeBlock>

<PromptCodeBlock>
관리자 테이블 편집 화면은 CSR로 만들어주세요.
행 선택, 인라인 편집, 필터 상태 변경이 즉시 반영되어야 하고, 사용자가 조작 중인 상태가 끊기지 않게 해주세요.
</PromptCodeBlock>

<Callout type="warning" title="CSR은 초기 빈 화면 문제를 함께 고려해야 합니다">
초기 HTML이 약하면 로딩 중 공백이 길어질 수 있습니다. 로딩 상태와 초기 경험을 같이 설계해야 합니다.
</Callout>

## 구현 체크리스트

- 브라우저 상호작용 중심 요구가 분명한가
- SEO보다 조작성이 더 중요한가
- 초기 로딩 상태를 고려했는가
- 서버 렌더링 없이도 사용자 경험이 자연스러운가
- 클라이언트 상태 관리가 과도하게 복잡해지지 않는가

## 자주 헷갈리는 개념 비교

### CSR vs SSR

- CSR은 브라우저가 화면을 조립합니다.
- SSR은 서버가 초기 HTML을 만듭니다.

### CSR vs 클라이언트 컴포넌트

- CSR은 렌더링 전략입니다.
- 클라이언트 컴포넌트는 브라우저에서 동작하는 컴포넌트 단위 개념입니다.

### CSR vs SSG

- CSR은 요청 후 브라우저에서 조립합니다.
- SSG는 빌드 시점에 HTML을 미리 만들어 둡니다.
