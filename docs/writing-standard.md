# 레퍼런스 문서 작성 기준

모든 문서는 아래 구조를 기본으로 따릅니다.

## 필수 섹션

1. 한 줄 정의
2. 왜 중요한지
3. 언제 쓰는지
4. 언제 쓰지 말아야 하는지
5. 비개발자가 자주 하는 모호한 요청
6. 더 좋은 요청으로 바꾸는 방법
7. 복붙 가능한 프롬프트 예시
8. 구현 체크리스트
9. 자주 헷갈리는 개념 비교
10. 관련 문서 링크

## MDX 컴포넌트 최소 사용 기준

- `Callout`: 최소 2개
- `PromptCard`: 최소 1개
- `PromptCodeBlock`: 최소 2개

## 품질 기준

- 정의보다 실전 지시력이 더 강해야 합니다.
- 기획 언어를 개발 언어로 번역하는 문장이 반드시 포함되어야 합니다.
- 프롬프트는 바로 복붙 가능한 문장이어야 합니다.
- 비교 섹션에는 비슷한 개념과의 차이가 명확해야 합니다.
- 관련 문서 링크는 최소 2개 이상 포함합니다.

## 상태 승격 기준

- `작성됨`에서 `기준 문서`로 올리려면 필수 섹션이 모두 있어야 합니다.
- 프롬프트 예시가 실제 렌더링되고 복사 기능이 동작해야 합니다.
- TOC에 들어갈 `##`, `###` 구조가 충분해야 합니다.
- 빌드와 문서 페이지 렌더링 확인이 끝나야 합니다.
